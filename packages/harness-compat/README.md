# `@paimind/harness-compat`

Version-scoped compatibility boundary for DeepSeek Harness and Cordis APIs.

Package rules: [Plugin Authoring Standard](../../docs/standards/plugin-authoring.md).

## Responsibility

The readonly session-artifact codec uses the original `session.history` tail
and `workspace.list`. The history owner supplies a single live/detached cut and
provider projections; no Agent is resumed. Successful append results are paired
only with root native mutation presenter locations in the same original turn.
Prose, directory contents, reads, deletes, failed calls and nested dispatch do
not imply produced files. The selected native client reducer is checked for
parity in tests, not embedded in production. History is bounded to 10000 events
and 2 MiB; incomplete or inconsistent cuts fail, never report an empty complete
list. Business projection validation remains in the artifacts package; this
codec neither authorizes a caller nor owns artifact state or file access.

Managed approval responses remain with the original ApiProxy pending owner.
The gateway carrier preserves its RPC ID and stamps a signed correlation of
the exact session, approval, decision and version. The managed provider checks
current authority both before and after original pending-state observation,
then strips private metadata before the original synchronous consumer. An
immutable getter permits Cordis service-proxy binding without permitting a
second response owner. Approve requires execution eligibility; reject is
current-login cleanup, not an execution grant. Native tool-time guards remain
independent. Non-approval question responses remain unchanged. A carrier
receipt proves neither persistence nor tool completion; versioned decision
commands and crash/browser acceptance remain separate requirements.

Stored approval and turn evidence uses the original persistence `readFrom`
operation. `inspect` can return a live in-memory view and is not a durability
witness. Approval `persisted` requires the exact terminal asked/decided pair
in original stored events; the reader never flushes, repairs or resumes a
session. That observation alone does not identify the command which caused a
decision, reconstruct a pending request or authorize tool replay.

The managed tool guard captures only the original preparation interval for an
exact tool call. If it contains an approval, body dispatch requires its single
matching allowed decision in the original stored prefix. The write-side
checkpoint uses SessionStore flush, verifies storage afterward and rechecks
the prepared deployment scope. Failure, missing writer, timeout, cancellation
or revocation denies the body. This is not an approval log, replacement
scheduler, or retry mechanism; ordinary non-approval calls stay with their
existing owner.

Managed profiles contribute a private, on-demand `paimindNativeConnectorReferences`
read to the existing launcher channel. It observes selected native MCP entries
in the original Loader tree, including effective parent disabledness and native
fiber state. It never evaluates configuration expressions or exposes URLs,
arguments, environment, headers, credentials or raw errors. `active` is only a
plugin lifecycle observation, not connection health or execution authorization.
There is no public RPC, connector registry, connection manager or new tool
allowlist. Cancellation/unload invalidates this stateless read. Configuration,
governance, real use and browser acceptance are still separate pending work.

An explicit managed-cell `nativeConnectorDirectory` adds original
`cordis:include` persistence under the exact private DSH Home child. The native
Include remains the sole file/entry owner; configuration writes admit bounded,
literal, disabled MCP records, with no arbitrary plugin/module/group/expression
input. Its private configuration operations create, edit or remove those records,
await the actual native writer and compare disk with original in-memory state.
Process-scoped keyed revisions detect stale changes without returning a raw
configuration digest. Secret-bearing files and native temporary files remain
private; a redirected, hard-linked or uncertain temporary file fails closed.
Disposal invalidates the service, but retains the native file for recovery.
Disabled configuration operations add no watcher, tool grant or external
connection; there is no new config registry. The existing admin durable
command/audit UI consumes this owner; the full approval-to-activation binding,
member grants and real use remain required.
A saved-disabled result cannot be treated as enabled or approved. New writes
require 1–10 reconnect attempts, including when reconnect is disabled, matching
the selected native schema. Previously retained disabled records with zero
remain readable/removable without a silent rewrite; explicit replacement must
use valid values. This read-only legacy exception is never activation approval.

Explicit new/replacement writes also store a private random version key in the
same original Loader entry. The internal `connector.release` read derives a
stable keyed reference from the actual canonical ID/provider/configuration;
it exposes neither that key nor a dictionary-testable unkeyed config digest.
This reference survives owner restart, while the existing process-scoped
optimistic revision intentionally expires. Changed/recreated entries rotate
the key; exact no-op writes and unrelated siblings preserve it. Legacy records
remain readable/removable and explicitly unversioned until a full valid write;
there is no startup migration. The old v1 configuration projection is unchanged.
The private reference is not an approval: governance must additionally bind
the exact tenant, member and admitted runtime, and verify current authority.
No activation or tool permission is granted by this operation.

The internal activation seam persists only enabled intent with an exact generated
native Loader dependency. Cold boot leaves that entry PENDING until a trusted
embedding callback revalidates its exact version and supplies a revocable lifetime;
there is no persisted ready/granted bit. The original provider owns startup,
connection, tools and teardown. Revocation withdraws the native dependency and
awaits its lifecycle, without rewriting intent or stopping sibling connectors.
Withdrawal during asynchronous checks invalidates the pending activation, and
failed native startups remain explicitly disableable. Request cancellation is
not rollback; a persisted enabled intent may remain safely gated after failure.
The old disabled-only configuration v1 projection refuses enabled rows instead
of falsely reporting them disabled; a distinct private lifecycle projection
describes intent, dependency lifetime and original fiber phase, never health or
tool permission. Managed bootstrap now composes this owner with the existing
private current-authority channel. Each exact approval revision owns a native
effect lifetime: serial 1-second renewal, independent 4-second maximum validity,
and a 1.5-second bounded authority request. Pending/late answers do not renew;
failure, revocation or control-lifetime disposal withdraws the original dependency.
The original tool dispatcher verifies exact native registration and active-turn
origins, checks current login/publication/connector authorization before dispatch
and again before returning its result, and fuses execution with the live lifetime.
A completed external side effect cannot be rolled back by a later denial.
The role floor conditionally admits only this exact composed native provenance;
no authority owner, copied tool or similar name gets an allowance.

The private `connector.restore` operation only revalidates already-persisted
enabled intent after the gateway reverse channel connects, including an explicit
single-cell replacement. It cannot enable a disabled record or accept caller
configuration; already-live entries also recheck current approval. Unapproved
entries remain pending; a lost reply is unconfirmed, not an automatic retry or
successful recovery. Original files are retained. This is not the administrator
durable enable/disable command, active-config management UI, final immutable
worker admission or browser acceptance; those remaining gates are unchanged.

`observeActivation` adds a redacted read of that same original Include, not a
second configuration owner. Only this compatibility layer translates the selected
native phase enum into `paimind.connector-observation/v1` names, sharing the
existing inventory conversion and refusing unknown values. Saved intent, gate
presence and provider phase remain distinct; connection is never probed. Existing
numeric internal lifecycle state and disabled configuration v1 are unchanged.
The private control read and audited original Settings observation are wired;
administrator write controls remain separate pending work.

The internal authority's `activate` accepts an optional exact approval revision
for the trusted administrator command path. Both original-owner permission
checks pin that revision rather than silently adopting a newer approval.
Existing private restoration still independently revalidates saved intent;
disable needs no current approval. This is an internal argument, not a new
public export, persisted grant, connection owner or browser invocation route.
The gateway now owns durable activation reservations and unknown historical
receipts; the original Settings write controls remain pending.

In a managed execution domain, the existing application-specific Loader seam
selects a stdio placement wrapper for the exact installed native MCP provider.
It keeps the original schema, service injection, async startup, connections,
reconnect policy, tool registration, dispatch and awaited disposal. Only launch
argv/cwd/environment pass through the existing prepared execution domain; all
ambient environment keys are tombstoned anew at every native reconnect. There
is no global SDK patch, second process owner or member grant. Retained wrappers
fail closed after disposal and cannot mount into another application root.
HTTP connectors use a capability-authenticated loopback byte relay to the exact
configured endpoint. It validates all DNS answers on every request and pins the
selected public address into the socket lookup, retains the original Host/SNI,
and explicitly verifies HTTPS certificates even if ambient TLS defaults differ.
Special/private/link-local/transition ranges, redirects, browser origins and
header-based target overrides are denied. Configured credentials stay on the
upstream side; cookies/forwarded headers and remote error bodies/auth challenges
are not reflected. Native session/version/replay headers and streaming bytes
remain intact; the native SDK still owns all protocol state and retries.
There are eight in-flight requests, a 1 MiB input/32 MiB per-stream output limit,
a 15-second input/DNS/response-header deadline and a 180-second socket-idle abort
per connector. Unload closes listeners and requests; failed native startup also
joins relay cleanup. No global fetch/SDK patch or new exported API is added.
Private enterprise destinations still require a separately verified deployment
permission; an administrator URL alone cannot grant internal-network access.
This connector-specific boundary is not full-cell outbound admission, governed
activation, member permission or browser acceptance. Non-managed profiles are
unchanged. The native package and SDK contracts are pinned in the compatibility
matrix; internal connector declarations are excluded from the pack.

The same managed Loader selection binds the exact native ToolRuntime constructor.
Only registrations made by the original MCP provider's async lifecycle acquire
ephemeral provenance: original Loader entry, provider incarnation and the exact
scoped definition/body. The original registry remains the only tool owner.
Policy projections receive optional immutable metadata, never configuration or
credentials. A prefix, foreign scoped shadow or copied body does not acquire it.
Prepared calls recheck the exact definition immediately before native dispatch,
after asynchronous wrappers; unload, reload, native list refresh or body mutation
cannot transfer an earlier approval to a replacement. Native list notifications
retain the provider lifetime but invalidate queued calls to old definitions.
This uses the pinned rc.2 private dispatch seam only on this managed instance,
not a global prototype patch. Source attribution is not enterprise permission;
the member floor still denies MCP pending the separate current-authority path.

The managed native API provider composes `projectPaimindNativeSessionList` to
correct rc.2 cold-list preset display through the original non-publishing
Session inspector and `resolveSessionPreset`. It changes only the response's
current preset field, not creation headers, history, bindings or authorization.
Four list requests and four per-request inspections are the concurrency bounds;
each request has a five-second deadline. Unload cancels pending work, and an
unverifiable row fails explicitly rather than displaying its creation preset as
the current selection. The existing native queue provenance guard remains in
the same provider. No additional registry, persistent projection or Agent is
created by listing.

Managed directory views read the original live or cold Session cwd without
resuming an Agent. The existing managed filesystem/subprocess owner pins that
directory in its read-only Linux world, uses native metadata operations, bounds
the detached result, and joins helpers on cancellation/unload. No browser cwd,
raw target key, private home or other member root becomes a read capability.
The sidebar adapter, not this package, owns its provider's display carrier.

Prompt correlation is a read-only client projection from exact native history.
The gateway carrier preserves the bounded browser RPC identifier for the
enterprise identity owner to sign; `readHarnessPromptCorrelation` in
`./client-surface` recovers that display identifier only for the selected
Session. It cannot authenticate a source, mint a login, authorize execution,
rewrite history or infer a missing legacy correlation. Identity retains HMAC,
current-login, cell and policy checks; derived/job sources do not inherit it.

Role: **Shared support package**. It has no independent Harness lifecycle or product surface; runtime packages consume its exported contract.

## Dependencies

- Internal runtime dependencies: `@paimind/contracts` (`workspace:^`).
- External runtime or peer dependencies: `@deepseek-ai/cordis` (`^4.0.1`), `@deepseek-ai/dsh-client-ui-primitives` (`0.1.0-rc.8`), `@deepseek-ai/dsh-agent` (`^0.1.0-rc.8`), `@deepseek-ai/dsh-llm` (`^0.1.0-rc.8`), `@deepseek-ai/dsh-schedule` (`^0.1.0-rc.8`), `@deepseek-ai/dsh-storage-domain` (`^0.1.0-rc.8`), `@deepseek-ai/dsh-settings` (`^0.1.0-rc.8`), `@deepseek-ai/dsh-tools` (`^0.1.0-rc.8`), `@deepseek-ai/dsh-typert-protocol` (`^0.1.0-rc.8`), `@deepseek-ai/schemastery` (`^3.18.1`).
- Client service injection: None.

The manifest is authoritative for dependency direction and version selection.

Managed boot additionally consumes the published `dsh-app-boot`, `dsh-cmdline` and `dsh-launch-environment` packages at the manifest's pinned version. These are already in the native runtime closure; no new runtime implementation or UI dependency is introduced.

Managed subprocess placement consumes the existing, pinned `dsh-subprocess` and `dsh-subprocess-local` packages directly. Its native executable-lookup helper also uses the existing Cordis dependency inside the confined execution world. These packages must be visible from the trusted module anchor; it does not fall back to host-side lookup when the confined lookup fails.

Managed filesystem placement additionally consumes the already selected `dsh-fs`, `dsh-fs-local`, `dsh-fs-sandbox` and `dsh-sandbox-policy` packages. The helper must resolve those exact native versions from the same immutable dependency world.

Managed directory selection directly consumes the existing native `dsh-host-directory-picker` service and `dsh-host-directory-picker-browse` implementation at the selected compatibility version. They were already included by the native web bundle. The filesystem service has no directory-creation operation, and the native browse provider has no root restriction; reusing that provider inside managed placement preserves its public contract without copying upstream source.

Native operation decoding consumes the published `dsh-host-apiproxy/api/rpc.schema` request and response schemas at that same pinned version. The adapter checks the exact method/path/envelope and distinguishes reviewed native capabilities without granting namespace-wide permissions. Known settings reads, writes and the external document opener have separate classifications; unknown methods in that native namespace are explicitly unsupported. Other unknown operations have no capability. Enterprise authorization remains the control plane's responsibility, and classification never proves object ownership or execution isolation.

## Lifecycle and failure

The fixed host-health readback calls only the original `host.describe` API and validates its published response schema and correlation. It returns no host paths or other fields, reads no HTML or session content, and is not a UI, model-call or admission check. The existing operator controller consumes it for technical liveness; deployment identity and current lease decisions remain outside this compatibility codec.

The gateway transport entry adds `createHarnessModelRead` and `decodeHarnessModelRead` for four exact native reads: redacted settings description, provider registration, model catalog and one explicitly named credential description. It projects only bounded default-selection, catalog and presence fields, drops raw settings/schema/base/user layers, endpoints, headers and error details, and rejects uncorrelated or malformed responses. It neither resolves credential values nor owns enterprise target authorization or a second model registry.

The same entry projects native model configuration revision/writability and
prepares exact default-model patches or a selected route's write-only named
credential change. These codecs never send or retry requests. Their caller must
reauthorize the administrator and exact member/cell revision, reserve a durable
command, and confirm its outcome. Generic native settings/credential rejection
may include a storage exception after persistence; it remains `unconfirmed`,
not proof of rollback. Only a correlated namespace/revision conflict proves a
stale settings write was refused. Native schemas/layers, secrets and error
messages are never returned. Omitting reasoning effort from a patch preserves
the original owner's setting. No member management permission is added.

The native `originCheck` may return a bounded set of opaque provenance
requirements. The existing active-turn watch retains their monotonic union,
passes it into every later step/tool/renewal check, and includes it in exact
delegation/job captures. It never caches an allow or owns a second Session.
Concurrent replies cannot erase a requirement; stale captures fail if the set
changes. Original turn end releases that watch, while an already-started native
job retains its captured requirements until settlement. Signed delegated/job
sources can carry requirements through native messages; the deployment's
identity owner, not this syntax adapter, verifies their authenticity. Complete
terminal-delivery and cold-process Skill lifecycle acceptance remains pending.

Subsequent turns and terminal captures reread existing signed requirements from
the original model-visible Session surface and its declared source-event graph,
including nested replacements. They recheck the current principal, not the old
sender's login. Unconsumed log-only inbox entries and source-looking prose do
not contribute. Messages actually selected by the original pre-step or terminal
owner also contribute their loaded-Skill requirements before first use.

Managed boot pairs `originCheck` with `skillUseCheck`. The latter verifies the
native loaded value against the original immutable Skill owner and current
authority, in process; bodies never enter the private authorization wire.
Explicit native invocations retain their identity/body with own provenance
metadata. Original `skill` results use native `additionalContexts`, including
the original composite ferry on failure/cancellation. No tool definition,
renderer, registry or history owner is replaced. Original continuable settlement
and JSONL cold-child recovery now carry newly loaded requirements, with a real
private/PG signing and parent-revocation combination. An unconsumed context
discarded by original cancellation is not reintroduced into later model history;
tests verify no intermediate body exposure. Complete process/final-image
recovery and Browser E2E remain unaccepted; enterprise admission stays closed.

Managed profiles may supply an image-owned `presetGuard` together with their tool guard. The root checks the native mounted preset (not a stale session header) before every native model step and tool dispatch. Missing identity, malformed policy results and provider withdrawal fail closed; this admission floor survives optional product-plugin unload. It is synchronous and does not pretend to implement live control-plane grant checks. `copyPaimindNativeStandardPreset` delegates only Standard copying to the native owner without accepting composition bytes or filesystem targets.

`readPaimindNativeSessionReference()` reads the original live Session Store, or
the original persistence owner's non-publishing `inspect` view for a cold
session. It validates the requested native identity and returns a detached,
read-only projection; it never loads, resumes, rewrites recovery logs or adds a
session registry. A live session published during inspection takes precedence.
Missing sessions, conflicting identities and inspection failures reject. The
caller owns binding/version/preset policy and must serialize its own writes.
Tests include a real native JSONL owner restart with unchanged history bytes
and rejection from a different private store; this is not browser acceptance.

`listPaimindNativeFirstHumanTurnReplies()` projects only model-message content
from completed steps of the first human-containing native turn, provided that
turn ended normally. Native sequence, turn/step pairing, appended surface,
model provenance and interruption checks stay in this compatibility boundary.
A queued input batch is one turn; later successes cannot validate an earlier
failed turn. The product consumer owns visible-content and configuration policy.
There is no new log, registry, background process or model invocation.

The managed profile can select `clientAudience: 'member'` from its trusted
deployment policy. Exact native management-only client rows are disabled using
the original Loader composition before bootstrap; their package identities must
match the pinned version. Default/admin compositions are unchanged. This is not
an authorization grant, a client-graph rewrite, or an enterprise acceptance claim.
It preserves native conversation, personal Agent and Workspace owners and does
not suppress Extension Center or third-party sidebar failures.

`installHarnessSettingsSectionVisibility()` reversibly projects the published native Settings navigation by exact contributed section ids. Its enterprise consumer owns the allowed ids, including the unverified-identity state; the adapter only joins those ids to unambiguous native buttons and invokes the existing fallback action. It restores original visibility on identity change, provider loss or unload, preserves native modal/content/focus ownership, and leaves unknown host markup untouched. It is not authorization and does not suppress RPC failures or prevent plugin startup requests.

Consumers import the public exports. The package registers no UI or services. `resolvePaimindProductCenterHost()` fails closed unless one live native `conversation` Slot anchor resolves to a non-body parent; `installPaimindProductCenterHost()` then leases that parent as the Portal host, makes only the native conversation subtree inert and accessibility-hidden, and restores every prior attribute when the final lease ends. The non-modal Center interaction moves focus into the opened page once and closes it on Escape without locking document scroll or trapping Tab navigation, so the native sidebar remains operable. The client-surface controller owns only document listeners and removes them on disposal. Incompatible imports fail through the exports or type boundary.

The `gateway-transport` document policy consumes only an admitted, trusted native root (GET `/` or `/index.html`). It hashes the published 0.1.1-rc.2 inline queue/graph/theme bootstrap without editing upstream HTML, and permits the native Cordis expression evaluator only in that document. Script URLs are limited to that gateway's native asset/module paths. This helper is not an HTML sanitizer; user files, unknown routes, login documents and API responses must not receive this policy. Oversized or unsupported bootstraps fail closed. The enterprise gateway keeps those other documents sandboxed and rechecks authority before returning the buffered root.

`prepareHarnessInteractiveRequest` validates the exact rc.2 `session.prompt`,
`subagent.prompt` and `session.updateQueue` carriers with upstream schemas. It replaces only the request
RPC ID with the enterprise gateway's signed login-source association and restores
only the HTTP response's top-level caller correlation after bounded validation.
Native message IDs, contents, timezone, histories, downlinks and approval-response
IDs remain owned and emitted by Harness. Unknown or aliased prompt carriers fail
closed. The signature and current login checks belong to the enterprise identity
owner, not this wire adapter. A source association is neither a bearer credential
nor a runtime permission: queue edits, native turn provenance, live resource policy,
revocation and independent background principals require separate enforcement.

`managed-runtime` can install `originCheck` on the original native model-step,
tool-preparation and tool-dispatch lifecycles. It reads the active native turn
and its messages, validates the final pre-step decision, and carries all signed
human sources from that turn (up to 64 unique sources). It never borrows a login
from an older turn or an arbitrary plugin/job message. Native dynamic system
context remains context, not user authority. Each check is asynchronous, bounded
and canceled on native interruption or root disposal; it is not installed as a
synchronous tool guard. Per-execution weak references only correlate the native
turn and exact mounted preset across preparation and dispatch. The mounted
native preset owner takes precedence; an unavailable mounted result never falls
back to an apparently valid session header. The managed launcher supplies the
private reverse-channel checker without passing credentials into native execution.
Its separate `runtime.authorize` operation reads the original adoption owner's
verified immutable receipt and sends only its identity and content digest. The
publication owner reuses current assigned-content policy in the same transaction
as exact login and pinned-cell checks. Author/reviewer access never becomes use
permission; withdrawal, explicit denial and group membership are re-read. The
login-only `identity.origins` result cannot satisfy execution authorization.
An admitted original turn also owns a serial current-authority renewal, checked
every second while active. Freshness expires five seconds after a successful
check started, never after a late reply; a stalled or disconnected checker cannot
retain an indefinite allow. New signed step sources are rechecked. Revocation,
preset drift and root disposal cancel that exact native turn with `keepInbox`,
preserving unstarted messages; native turn end releases its timers and a late
reply cannot cancel a replacement turn. Tool dispatch joins the renewal signal
to the original registry signal and waits for the original body to settle.
Cancellation is cooperative, not rollback of completed effects or a hard kill
of arbitrary synchronous code. Actual provider/container teardown still needs
immutable-image acceptance. Independent background principals remain separate
gates; the enterprise preset floor stays closed until the complete authorization
chain is verified.

The same managed Loader also derives the exact installed native local Jobs
provider when `originCheck` is present; readiness rejects absent or bypassed
job authority. A producer must belong to an actual admitted active native turn.
After native preflight, its running job retains the exact initiating source
set and mounted preset, independently of subsequent turns or logins. Renewal
continues after turn end, stays serial and bounded, and expires five seconds
after the successful check started. Logout, member suspension, binding changes,
scope drift or an unavailable checker request cancellation through the original
registry. If its producer throws from cancellation, the existing owned-cell
shutdown path is requested; that is not proof of successful producer cleanup.
Original IDs, capacity checks, owner access, streaming cursors, terminal promise,
completion ordering and native service cleanup remain unchanged. Producer and
controller withdrawal do not remove an accepted job's authorization renewal;
settlement and the actual Jobs service lifecycle release it. This covers bounded
continuations of interactive authority, not an independent scheduled principal,
nor permission for unsigned `tool-jobs` or `schedule` completion messages. The
enterprise execution floor remains closed pending those distinct integrations.

Optional `jobOriginSeal` pairs with execution/queue authority and wraps only the
exact installed native `tool-jobs` completion controller. It requests a bounded
private `runtime.job-origin` signature for the original login, same session,
mounted preset and native job ID; the native notice cannot borrow a newer login.
Current identity, binding and immutable publication are verified before signing
and again at actual execution. A transient attachment is discarded at native
settlement; it owns no job record, status, output, history or schedule. While the
original synchronous controller sends once, its exact owner method receives the
signed source, then the original descriptor is restored. Original formatting,
read/wait reporting, quiet/wakeup decisions and wake budgets remain native-owned.
Withdrawal of controller, job service or owner aborts pending signing. A native
reader/canceller winning the race suppresses delivery; unknown method owners are
not overwritten. The known native-child followup guard composes explicitly.
Original JSONL history retains these source fields. Local-only model fixtures
and service reconstruction do not establish browser or final-image acceptance.
Unsigned plugin messages and independent scheduled principals remain denied.

Managed bootstrap pairs `originCheck` with `queueCheck`. Its existing single
Loader selector derives the original API provider without replacing its config,
injection or non-queue methods; readiness rejects an unguarded provider. Queue
checks bind the actual editor's signed login to the current native session and
preset. After bounded authorization, the exact pending message and target must
still match; a later edit, removal, owner withdrawal or preset change fails
closed. The rc.2 operation retains its original text-only, missing-item,
subagent-ownership and steering decisions. Its synchronous edit/steer mutation
receives the editor source through a temporary exact-object projection restored
before returning, never across an await or on a prototype. Native message IDs,
order, timezone and durable inbox events remain original; no message/identity
map or second history is added. Removal checks current identity/binding only,
so withdrawn execution permission does not prevent canceling unstarted work.
Editing or steering requires current execution authorization, and the resulting
message is checked again when it actually runs. Retained withdrawn API objects
cannot operate, and a competing mutation owner is never overwritten.
