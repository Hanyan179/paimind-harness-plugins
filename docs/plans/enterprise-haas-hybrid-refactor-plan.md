## 2. 一句话决策

PAIMind 企业线采用 Hybrid HaaS Architecture（混合式服务化智能体骨架架构）：保留现有企业线的 Control Plane（控制面）、企业 Gateway（网关）、发布治理、审计和隔离 Runtime Cell（运行单元），引入标准 OpenAPI（开放接口规范）、SSE（服务器推送事件）、独立前端壳、外部状态层和可调度运行单元池；Cordis 子 Context（上下文）只承担会话能力组合，不承担不可信租户的安全隔离。

## 3. 为什么这样改

### 3.1 当前企业线已经解决的问题

旧企业线已经形成以下可复用资产：

- 企业身份、租户、用户和访问策略基础；
- Gateway（网关）身份清洗、内部身份签名和失败关闭；
- 不可变 Agent/Skill Release（智能体／技能发布版本）目录；
- 会话与精确发布版本的绑定；
- 每用户独立容器、网络、数据卷和资源限制；
- 追加式 Audit Log（审计日志）；
- Runtime Broker（运行实例调度器）和企业管理基础能力。

这些能力证明了安全与治理方向，但尚未完成真实企业验收，不能作为已经发布的产品能力。

### 3.2 当前企业线的结构性限制

- 客户前端仍依赖完整 DSH Web（宿主网页端）和客户端 Cordis 插件图，无法独立演进；
- 外部调用仍主要代理宿主原生通信，不是稳定、版本化的企业 API（应用编程接口）；
- 每个用户运行完整容器，隔离强，但成本和扩缩颗粒度较粗；
- 会话和工作区主要留在用户数据卷，跨实例恢复和故障迁移能力不足；
- 固定镜像和固定 Cordis Patch（插件组合补丁）不能等同于按场景治理的 Plugin Registry（插件注册中心）；
- 本地身份实现可用于开发和验证，不能替代企业 OIDC（开放身份连接）集成；
- 旧企业工作区与当前产品线高度分叉，不适合直接合并或继续堆叠。

### 3.3 外部 HaaS 思路值得吸收的部分

- 将 Harness（智能体骨架）能力集中供应；
- 通过 OpenAPI（开放接口规范）和事件流解除前后端同构绑定；
- 建立独立 Control Plane（控制面）与 Data Plane（执行面）；
- 将状态逐步外部化，支持故障恢复和多副本调度；
- 建立集中化发布、权限、配额和审计体系。

### 3.4 不直接采用的部分

- 不把同一进程中的 Cordis 子 Context（上下文）当作企业租户安全边界；
- 不在每次创建会话时从外部下载和执行任意插件；
- 不把业务规则、审批、权限和审计编排下放给前端；
- 不让 Redis（内存数据存储）成为会话与审计的唯一事实源；
- 不在第一阶段直接追求完全无状态的 Agent Step（智能体执行步骤）。

## 4. 目标与非目标

### 4.1 目标

1. 集中供应会话、智能体循环、工具执行、审批、工作区、产物和审计能力。
2. 允许客服壳、编码壳、分析壳和业务壳独立开发、部署与升级。
3. 在不降低企业隔离强度的前提下逐步提高运行密度。
4. 支持租户、用户、场景、Agent Release（智能体发布版本）和 Skill Release（技能发布版本）的确定组合。
5. 支持运行实例故障后的会话恢复、事件续传和工作区恢复。
6. 保持 Harness（智能体骨架）对原生 Session、Workspace、Tool、Skill Registry 和 Tool Execution（会话、工作区、工具、技能注册与工具执行）的唯一运行时所有权。
7. 形成可自动测试、可浏览器验收、可回滚和可审计的企业发布链路。

### 4.2 非目标

- 第一阶段不实现跨地域多活；
- 第一阶段不承诺完全无状态执行实例；
- 不重写 Harness（智能体骨架）执行循环；
- 不复制 Harness（智能体骨架）的 Session、Workspace、Skill Registry 或 Tool Execution（会话、工作区、技能注册与工具执行）成为第二套运行时；
- 不允许普通用户动态安装未经审核的运行插件到共享实例；
- 不把现有旧企业分支直接合并进产品主线；
- 不用产品负责人后续 UAT（用户验收测试）替代研发测试、安全测试和运维验证。

## 6. 三层边界

| 边界 | 权威载体 | 负责内容 | 明确不负责 |
| --- | --- | --- | --- |
| Security Boundary（安全边界） | 容器或后续经验证的虚拟机沙箱 | 租户隔离、文件隔离、密钥隔离、资源限制、故障影响范围 | 不由 Cordis 子 Context（上下文）代替 |
| Composition Boundary（组合边界） | Cordis 子 Context（上下文） | 会话对应的 Agent、Skill、Tool、模型和场景组合 | 不作为不可信租户隔离证明 |
| Scaling Boundary（弹性边界） | Runtime Cell Pool（运行单元池） | 实例分配、容量、租约、健康检查、滚动升级和恢复 | 不拥有业务身份或产品资源目录 |

第一阶段继续采用用户独享 Runtime Cell（运行单元）。只有完成同租户多会话隔离、资源竞争和故障影响测试后，才允许一个运行单元承载多个会话 Context（上下文）。不同不可信租户默认不共享进程。

## 7. 分层职责与所有权

| 层 | 唯一所有者 | 核心职责 |
| --- | --- | --- |
| 前端体验层 | 各业务前端产品 | 交互、渲染、品牌、场景入口、客户端草稿和用户输入；不保存服务端权限事实 |
| 企业接口层 | PAIMind Gateway（网关） | TLS（传输层加密）、OIDC（开放身份连接）、令牌校验、租户绑定、限流、幂等、版本协商、事件续传 |
| 企业控制面 | PAIMind | 身份投影、策略、资源发布、外部会话句柄、运行映射、审批、配额、审计和运维控制 |
| 原生执行运行时 | Harness（智能体骨架） | 原生 Session、Workspace、Agent Loop、Tool、Skill Registry、Job 和 Tool Execution（会话、工作区、智能体循环、工具、技能注册、任务与工具执行） |
| 运行适配层 | `@hansen/harness-compat` | 选定 Harness（智能体骨架）版本的接口、事件、恢复和兼容投影 |
| 能力供应面 | PAIMind 发布治理＋Harness Loader（宿主加载器） | 已批准插件组合的不可变发布、安装、启停、镜像和摘要校验 |
| 权威数据层 | 对应领域服务 | PostgreSQL（关系数据库）保存控制事实；对象存储保存文件与产物；Redis（内存数据存储）只保存可重建状态 |

### 7.1 会话双层身份

控制面可以拥有面向外部 API（应用编程接口）的 `sessionId`，但不得复制一份独立的完整 Harness Session（宿主会话）历史。每条映射至少包含：

- `tenantId`
- `subjectId`
- `scenarioId`
- `compositionReleaseId`
- `runtimeCellId`
- `nativeSessionId`
- `status`
- `version`
- `createdAt` / `updatedAt`

外部事件是原生 Harness Event（宿主事件）的稳定投影。当前 Harness（智能体骨架）不接受的未知持久化事件不得写回原生 Session（会话）；平台事件保存在控制面事件记录中，并通过明确关联字段与原生会话对应。

### 7.2 业务编排边界

前端只负责体验编排。以下行为必须留在控制面或执行面：

- 权限判断和策略解析；
- Agent/Skill Release（智能体／技能发布版本）选择；
- 工具审批状态机；
- 配额、限流和成本控制；
- 有副作用工具的幂等、重试与补偿；
- 审计记录；
- 会话恢复和工作区一致性。

## 8. 北向接口基线

正式开发前先冻结 OpenAPI 3.1（开放接口规范）和事件 Schema（结构定义）。第一版接口以业务资源和用户动作为中心，不直接暴露 Typert（宿主类型通信）或 Cordis 内部对象。

### 8.1 核心接口草案

| 动作 | 接口草案 | 结果 |
| --- | --- | --- |
| 创建会话 | `POST /haas/v1/sessions` | 返回外部会话身份、固定组合版本和当前状态 |
| 查询会话 | `GET /haas/v1/sessions/{sessionId}` | 返回用户可见状态与运行位置抽象，不暴露内部容器信息 |
| 提交一轮 | `POST /haas/v1/sessions/{sessionId}/turns` | 返回 `turnId`，通过幂等键避免重复执行 |
| 取消一轮 | `POST /haas/v1/sessions/{sessionId}/turns/{turnId}/cancel` | 请求安全取消并返回确定状态 |
| 订阅事件 | `GET /haas/v1/sessions/{sessionId}/events` | 使用 SSE（服务器推送事件）发送增量事件并支持断线续传 |
| 审批工具 | `POST /haas/v1/approvals/{approvalId}/decision` | 批准或拒绝一次待处理工具动作 |
| 查询文件 | `GET /haas/v1/sessions/{sessionId}/files` | 返回受权限约束的工作区文件目录 |
| 上传文件 | `POST /haas/v1/sessions/{sessionId}/uploads` | 返回短时、单次、范围受限的上传凭证 |
| 查询产物 | `GET /haas/v1/sessions/{sessionId}/artifacts` | 返回结构化产物引用、类型和可用状态 |

### 8.2 接口必须具备的合同

- 所有写操作支持 `Idempotency-Key`；
- 所有事件包含 `eventId`、`sessionId`、`turnId`、`sequence`、`type`、`occurredAt`、`schemaVersion` 和受类型约束的 `payload`；
- SSE（服务器推送事件）支持 `Last-Event-ID` 和从权威游标恢复；
- 会话更新使用版本号或 ETag（实体标签）防止并发覆盖；
- 统一定义认证、授权、限流、冲突、暂不可用、超时和恢复中错误；
- API（应用编程接口）版本与 Agent/Skill Composition Release（智能体／技能组合发布版本）分开管理；
- Browser Client（浏览器客户端）只能看到业务身份，不能提交可信 `tenantId`、角色或内部运行实例身份；
- SDK（软件开发工具包）由冻结合同生成，前端不得复制手写第二套接口类型。

## 9. 事件与运行生命周期

### 9.1 会话创建

1. Gateway（网关）完成企业身份认证并生成可信主体。
2. 控制面校验场景权限、配额和目标组合发布版本。
3. Runtime Broker（运行实例调度器）分配或恢复符合安全域与版本要求的 Runtime Cell（运行单元）。
4. 运行单元创建原生 Harness Session（宿主会话）。
5. 控制面原子保存外部会话与原生会话映射。
6. 返回外部会话身份和事件订阅入口。

### 9.2 会话运行

1. 前端提交用户消息和幂等键。
2. 控制面重新检查用户、会话、组合发布和运行实例授权。
3. 执行面运行原生 Agent Loop（智能体循环）。
4. 原生事件被转换为稳定企业事件并按序发送。
5. 工具需要审批时，运行进入等待状态；审批决定由服务端恢复原轮次。
6. 完成后更新会话游标、运行摘要、用量和审计记录。

### 9.3 故障恢复

1. 调度器检测运行单元失联并停止继续路由。
2. 控制面冻结会话写入租约，避免双写。
3. 新运行单元取得同一组合发布、会话映射和工作区状态。
4. 恢复原生会话，校验最后权威事件序号和未决审批。
5. 只有恢复校验通过后才重新开放写操作；恢复期间前端收到明确状态。

## 10. 状态与数据设计

| 数据 | 权威存储 | 规则 |
| --- | --- | --- |
| 租户、用户、组织和身份映射 | PostgreSQL（关系数据库）＋企业身份源 | 本地密码仅作为开发适配器，不是生产唯一身份源 |
| 权限策略、配额和发布目录 | PostgreSQL（关系数据库） | 所有变更版本化并可审计 |
| 外部会话与原生会话映射 | PostgreSQL（关系数据库） | 唯一映射、乐观并发控制、失败关闭 |
| 原生会话记录 | Harness（智能体骨架）权威存储 | 不复制完整对话成为第二事实源 |
| 企业事件投影与审计 | PostgreSQL（关系数据库）或专用追加式事件存储 | 可回放、不可静默改写、与原生事件关联 |
| 工作区文件和产物字节 | 第一阶段用户卷；后续对象存储 | 迁移前后保持 Workspace Identity（工作区身份）、摘要与访问控制 |
| 路由、租约、短期缓存 | Redis（内存数据存储） | 可重建，不作为会话或审计唯一事实源 |
| 密钥与外部凭证 | 企业 Secret Store（密钥服务） | 不进入数据库明文、镜像、日志、前端或审计正文 |

工作区外部化采用渐进方式：第一阶段保留独立数据卷；第二阶段加入文件清单、摘要、版本和对象存储适配；只有完成并发写、崩溃恢复、大文件、权限和回滚验证后，才能把本地卷降级为缓存。

## 11. 插件与组合发布模型

### 11.1 注册中心定位

Plugin Registry（插件注册中心）是受控供应目录，不是第二个 Harness Plugin Registry（宿主插件注册表），也不是允许任意代码即时进入共享运行时的市场。

它负责保存：

- 插件身份、版本、来源、摘要和签名；
- 兼容的 Harness（智能体骨架）版本；
- 服务端、客户端、工具、权限和数据迁移声明；
- 安全扫描、许可证、测试与发布状态；
- 不可变 Composition Release（组合发布版本）；
- 镜像、回滚版本和运行约束。

Harness Loader（宿主加载器）继续拥有实例内真实插件加载和生命周期。PAIMind 负责选择哪一个已批准组合进入哪类运行单元。

### 11.2 发布与加载规则

- 场景引用确定的 `compositionReleaseId`，不得引用浮动最新版；
- 运行单元启动前校验镜像、组合和包摘要；
- 新发布默认用于新会话，通过滚动升级进入新运行单元；
- 运行中的会话不热切换 Agent/Skill/Plugin Release（智能体／技能／插件发布版本）；
- 禁止在用户请求路径上临时下载和执行未经预热的插件；
- Source Plugin（来源插件）的 Skill、Tool、Prompt Section 和 Client Capability（技能、工具、提示词段和客户端能力）必须同生命周期启停；
- Business Skill（业务技能）继续由 Skill Center（技能中心）管理用户可用性与作用域，不进入全局系统技能根目录；
- 前端业务壳作为独立应用发布，不伪装成仅服务端可用的 UI Plugin（界面插件）。

## 12. 安全模型

### 12.1 身份与授权

- 生产环境接入 OAuth2（开放授权）／OIDC（开放身份连接）企业身份源；
- JWT（令牌）只在边缘验证，内部使用短时、受众受限、可轮换的签名主体；
- Gateway（网关）删除浏览器提交的身份、租户和角色头；
- 每次创建会话、提交轮次、工具审批、文件访问和管理动作均重新授权；
- RBAC（基于角色的访问控制）负责角色基线，Resource Policy（资源策略）负责租户、用户、场景和资源级授权；
- 会话身份必须绑定租户、用户和精确资源，不允许凭已知 ID（标识）越权访问。

### 12.2 运行隔离

- 不可信租户不共享进程；
- Runtime Cell（运行单元）使用独立文件系统范围、网络策略、系统用户、密钥投影和资源上限；
- 工具权限由服务端策略与运行时 Allowlist（允许列表）共同收敛；
- 外部网络访问默认拒绝，按工具、域名和场景显式开放；
- 高风险工具必须支持审批、超时、幂等和审计；
- 禁止把 Cordis 子 Context（上下文）隔离测试替代容器逃逸、文件串读和网络越权测试。

### 12.3 审计

审计至少覆盖登录、登出、会话创建、组合解析、轮次开始与结束、模型调用摘要、工具请求与结果、审批、文件读写、发布、分配、撤销、运行迁移和管理员操作。审计失败时，高风险写操作失败关闭。

## 14. 分阶段改造路线

### Phase 0：方案冻结与安全恢复

目标：安全恢复企业线工作，不延续旧分支污染。

行动：

1. 回读本方案、旧暂停检查点和旧验收权威。
2. 只读确认当前产品线与旧企业线的 Branch、HEAD、Dirty/Untracked State（分支、提交和已修改／未跟踪状态）。
3. 回读旧企业容器、数据卷、镜像、端口和构建状态；不得删除旧资源。
4. 为旧企业工作区生成新的文件清单、摘要和分叉清单，将其冻结为 Legacy Reference（旧实现参考）。
5. 从用户确认的干净 Product Line Commit（产品线提交）创建新的独立工作树和 `codex/enterprise-haas-hybrid-refactor` 分支。
6. 不直接 Merge（合并）、Rebase（变基）或复制整个旧企业工作区。

交付物：恢复预检报告、旧资产清单、新基线身份、分叉处置表。

退出门禁：三个工作区互不写入；旧资源完整保留；新工作树干净；所有要迁移的企业资产都有保留、重构或淘汰结论。

### Phase 1：合同与控制面骨架

目标：先建立稳定外部合同，再迁移运行能力。

行动：

1. 冻结会话、轮次、事件、审批、文件和产物的 OpenAPI 3.1（开放接口规范）。
2. 冻结事件信封、错误模型、幂等、版本和断线续传合同。
3. 重构企业身份、访问策略、资源发布和会话映射领域边界。
4. 保留现有用户独享 Runtime Cell（运行单元），由新控制面通过适配层调用。
5. 建立 Schema Migration（结构迁移）、回滚和兼容策略。

交付物：接口规范、事件规范、生成式 SDK（软件开发工具包）、控制面服务骨架、迁移设计和合同测试。

退出门禁：接口结构校验通过；生成的客户端可构建；身份不可由浏览器伪造；同一幂等键不重复执行；控制面没有复制完整原生会话历史。

### Phase 2：独立前端与最小闭环

目标：证明前端能够脱离 DSH Web（宿主网页端）独立运行。

最小闭环：

1. 企业登录；
2. 创建会话；
3. 提交一轮；
4. 实时显示模型、工具与状态事件；
5. 完成一次工具审批；
6. 查看并下载一个工作区产物；
7. 刷新页面后从事件游标恢复；
8. 在企业管理端查到对应审计记录。

交付物：独立 Reference Shell（参考前端壳）、真实 Gateway（网关）、控制面、一个用户独享工作实例和端到端证据。

退出门禁：参考前端不依赖 DSH Client Cordis Tree（宿主客户端插件树）；完整闭环通过真实浏览器；控制台、网络、事件顺序和审计回读无未解释错误。

### Phase 3：状态外部化与故障恢复

目标：运行实例故障不再等同于会话永久丢失。

行动：

1. 外部化会话映射、事件游标、未决审批、用量和运行租约。
2. 建立工作区文件清单、摘要、对象存储和本地物化适配。
3. 完成运行实例宕机、进程重启、网络中断和恢复中的写入保护。
4. 建立 Backup/Restore（备份／恢复）、Failure Rollback（失败回滚）和 Version Rollback（版本回滚）。

退出门禁：故障恢复后无重复工具副作用、无事件倒退、无文件丢失、无跨用户串读；RPO（数据恢复点目标）与 RTO（恢复时间目标）由真实测量确定并记录。

### Phase 4：运行单元池与同安全域多会话

目标：在保持安全边界的前提下提高密度和弹性。

行动：

1. Runtime Broker（运行实例调度器）按租户、安全域、组合版本、容量和健康状态调度。
2. 同一可信安全域内允许一个 Runtime Cell（运行单元）承载多个会话子 Context（上下文）。
3. 增加 CPU（处理器）、内存、文件句柄、并发工具和模型配额保护。
4. 支持 Drain（排空）、滚动升级、故障迁移和容量扩缩。
5. 以现有 10/30 用户负载场景作为回归下限，新的容量目标由真实压测形成，不在方案阶段编造。

退出门禁：同单元会话零串读；单会话资源耗尽不拖垮其他会话；扩容、缩容、排空和恢复均有机器证据。

### Phase 5：企业强化与发布切换

目标：达到可交付、可运维、可回滚的企业版本。

行动：

1. 接入企业 OIDC（开放身份连接）和密钥服务。
2. 完成插件组合发布、签名、扫描、滚动升级和回滚。
3. 完成安全、接口、运行、浏览器、运维、可访问性和负载全量验收。
4. 建立告警、仪表盘、容量规划、值守和故障手册。
5. 新旧入口并行验证后再决定切换；旧企业线在回退窗口内保持只读可恢复。

退出门禁：所有 Release Gate（发布门禁）通过；没有跳过或待定的阻断项；产品负责人完成 UAT（用户验收测试）并明确签署业务验收结论。

## 15. 验收体系重构

旧企业线的 60 个场景、8 个质量门禁和 8 个完整门禁仍是历史权威，但不能直接作为新架构的固定分母。Phase 1（第一阶段）完成后，需要建立新的 Requirement-to-E2E Matrix（需求到端到端矩阵）：

### 15.1 必须继承的场景

- 登录、登出、会话失效和多标签页；
- 用户 A／B 与租户之间零串读；
- 已知 ID（标识）越权拒绝；
- Agent/Skill Release（智能体／技能发布版本）的提交、批准、分配和撤销；
- 新会话和新轮次的动作时授权；
- 审计不可删除和原因可查；
- 数据库迁移、备份、恢复和版本回滚；
- 运行实例资源限制、双实例和负载场景。

### 15.2 必须新增的场景

- OpenAPI（开放接口规范）兼容性和生成式 SDK（软件开发工具包）；
- SSE（服务器推送事件）顺序、断线、续传、重复和背压；
- 幂等提交、重复审批和有副作用工具恢复；
- 独立前端不加载 DSH Web Client（宿主网页客户端）；
- 运行实例故障迁移和恢复期间写入保护；
- 对象存储文件摘要、权限、大文件和并发写；
- 同安全域多会话 Context（上下文）隔离；
- 插件组合发布摘要、签名、滚动升级和回滚；
- Redis（内存数据存储）清空后权威状态仍可恢复；
- 控制面多副本下的租约、单写者和并发冲突。

### 15.3 验收层级

| 层级 | 责任 | 完成标准 |
| --- | --- | --- |
| Contract Test（合同测试） | 研发 | 接口、事件、状态迁移、权限与错误合同通过 |
| Component/Integration Test（组件／集成测试） | 研发 | 真实数据库、缓存、对象存储和运行实例组合通过 |
| Security Test（安全测试） | 安全与研发 | 身份伪造、越权、串读、密钥、网络和资源隔离通过 |
| Operational Test（运维测试） | 运维与研发 | 构建、部署、扩缩、排空、备份、恢复和回滚通过 |
| Browser E2E（浏览器端到端） | 测试与产品 | 独立前端真实用户链路通过，证据可回读 |
| UAT（用户验收测试） | 产品负责人 | 核心业务场景、体验和价值达到上线标准 |

产品负责人后续测试属于 UAT（用户验收测试），应当发生在研发合同、集成、安全和运维门禁基本通过之后，不承担发现全部底层工程缺陷的责任。

## 17. 风险与控制

| 风险 | 影响 | 控制方式 |
| --- | --- | --- |
| 旧企业工作区与产品线分叉严重 | 合并覆盖新产品能力 | 新工作树、逐资产语义迁移、禁止整体合并 |
| 隐含依赖 DSH Web（宿主网页端） | 独立前端仍被宿主版本锁定 | 以无宿主客户端模块的参考前端作为强制验收 |
| 子 Context（上下文）被误作安全边界 | 跨租户串读或故障扩散 | 容器／虚拟机继续作为不可信边界 |
| 事件双写或顺序漂移 | 刷新后消息重复、丢失或倒退 | 单调序号、幂等键、权威游标和单写租约 |
| 工具重试产生重复副作用 | 数据或外部系统被重复修改 | 工具级幂等、审批身份、执行收据和补偿策略 |
| 工作区外部化过早 | 文件冲突、性能下降、恢复失败 | 分阶段迁移，数据卷先保留，对象存储后验收 |
| 动态插件供应链风险 | 任意代码进入共享运行时 | 签名、摘要、扫描、不可变组合、预构建镜像 |
| Redis（内存数据存储）被当作事实源 | 重启后状态丢失 | 只保存可重建缓存、路由和租约 |
| 产品负责人承担全部测试 | 工程质量问题进入业务验收阶段 | 分层门禁，研发和运维先完成技术验收 |
| 过早追求完全无状态 | 复杂度和交付周期失控 | 先交付接口门面和隔离运行单元，再由数据决定演进 |

## 19. 全量完成定义

企业线重构只有同时满足以下条件，才能称为完成：

1. 目标架构中的每个领域和可写状态都有唯一所有者；
2. 外部前端只依赖稳定接口和生成式 SDK（软件开发工具包）；
3. 原生 Harness（智能体骨架）对象没有被影子运行时复制；
4. 不可信租户具有真实进程或虚拟化隔离；
5. 会话、事件、审批、文件和产物能够在运行实例故障后恢复；
6. 插件组合发布可验证、可升级、可回滚；
7. 合同、组件、集成、安全、运维和浏览器端到端门禁全部通过；
8. 所有机器报告为零失败、零跳过、零待定；
9. 产品负责人完成真实业务 UAT（用户验收测试）；
10. 发布、回滚、数据恢复和故障处置均有可执行手册和真实证据。

在以上条件完成前，只能分别陈述“方案已形成”“源码已实现”“定向测试通过”“集成环境通过”或“待产品验收”，不得提前声明 Release Ready（可发布）。
