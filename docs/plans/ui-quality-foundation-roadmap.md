# 界面质量与统一基座长期计划

## 1. 目标与执行约定

先恢复已有能力的正确性，再建设统一 Design System（设计系统）基座，随后逐个插件完成缺陷修复、界面调整、真实浏览器验证和用户评审。统一的是视觉语言、交互规则和状态表达，各业务插件继续拥有自己的业务流程与数据。

用户已明确的工作顺序（2026-09-07 最新授权）：

1. 已有 Bug（缺陷）优先，不能用界面美化掩盖功能失败。
2. 先完成核心定义和可运行的共享基座，再逐个插件迁移。
3. 动效属于 Personalization（个性化）：用户自己决定是否开启，不把统一降低或删除动效作为优化目标。
4. 按最新指示完成整个长期计划：批量检查全部插件，并补齐真实生成、保存、采用、运行和恢复流程；不再逐插件等待用户确认。实现和证据仍按插件记录，不能用已可访问页面代替全部流程。
5. 整体系统面向业务用户；字段、说明、示例、按钮及反馈按[基座文案规则](../standards/ui-foundation.md#面向业务用户的命名与文案)统一审阅，不直接沿用聊天产品或开发者界面的命名。

这条工作流为批量检查与集中交付计划，不创建后台定时任务，不扩大到尚未确认的新产品能力，也不自行授权提交、合并或发布。用户于 2026-09-07 另行明确授权本轮提交及合并本地主线；远端推送与发布另行处理。

## 3. 分阶段交付

| 阶段 | 工作内容 | 退出条件 |
| --- | --- | --- |
| 0：真实基线与阻断修复 | 建立隔离环境，复现入口、保存、执行、恢复等已有问题；先修阻断访问、数据正确性和原生交互的问题 | 有本轮缺陷与证据清单；共享阻断问题已修复或准确定位，剩余问题归入对应插件 |
| 1：基座首版 | 固化设计变量、基础组件、状态、浮层、焦点、响应式、主题及动效契约；完成最小真实消费路径 | 运行效果和可逆性可检验；用户看过并确认基座方向 |
| 2：逐插件迁移 | 按插件逐项记录并批量推进；先修已有缺陷，再按基座调整界面 | 当前插件技术门禁与可检查真实流程通过，记入集中交付清单 |
| 3：完整组合回归 | 验证迁移后的全产品组合、依赖级联、跨插件交互与卸载恢复 | 所有范围内入口已覆盖；缺陷、上游问题和未验收项均有准确结论 |
| 4：持续维护 | 后续新插件按同一基座接入；基座变更回归真实消费者 | 规则、实现和验收一致，例外有业务依据；不重新复制通用组件 |

本轮阶段 0–3 的实施、技术门禁及本地预验收已完成；用户效果确认尚未记录。阶段 4 为后续按需维护约定，不创建后台自动任务。

阶段 0 不先重写所有业务页。能够独立修复的严重缺陷先处理；依赖共享机制的缺陷与阶段 1 一起解决。后续每个插件仍执行“缺陷先于视觉”的同一顺序。

不预设缺乏依据的工期。基线完成后按已复现问题、依赖和验收成本估算当前单元；不为每个插件预先承诺相同天数。

## 4. 核心定义与包职责

采用“一个统一定义、多个明确实现所有者”。核心定义以现有 `@paimind/ui-foundation` 为中心扩展，不新增重复核心包，也不把所有页面搬进核心。

| 所有者 | 核心职责 | 明确边界 |
| --- | --- | --- |
| `@paimind/ui-foundation` | Design Tokens（设计变量）、基础控件、共享状态样式、通用交互契约与无宿主版本依赖的复用逻辑 | 无业务数据、无第二套设置存储、无宿主页面结构猜测；保留共享支持包角色 |
| `@paimind/visual-experience` | 共享视觉运行行为、主题叠加、布局密度、视觉偏好解析与订阅、可逆外壳呈现 | 不拥有业务页面和业务状态 |
| `@paimind/harness-compat` | 宿主版本、原生槽位、输入控制器、中央区域挂载、语义标记和原生恢复 | 不决定业务页面的信息结构 |
| `@paimind/user-settings` | 个性化设置页面；继续拥有用户背景、协作风格和自定义指令 | 界面偏好通过来源插件的公开契约展示和修改，不复制字段，不进入模型上下文 |
| 各业务插件 | 业务内容、流程、校验、保存和局部布局 | 使用共享定义；不直接覆盖宿主结构或独立复制通用机制 |
| `@paimind/better-sidebar-adapter` | 外部侧栏提供方的接口和文件查看能力转换 | 不修改提供方源码，不创建第二套侧栏 |

基座首版的核心定义：

| 定义面 | 需要统一的内容 | 允许的业务差异 |
| --- | --- | --- |
| 视觉变量 | 语义色、字阶、行高、间距、圆角、边框、阴影、焦点、层级、动效时长与缓动 | 业务状态由业务判断，再映射到语义变量；不按插件另造整套色板 |
| 基础控件 | 按钮、输入、选择、搜索、标签页、状态标识、提示、折叠、确认与反馈 | 只抽取已有真实消费者需要的部分，优先复用可用的原生组件 |
| 页面结构 | 页头、操作区、列表、详情、编辑区域、空状态、加载、错误和重试 | 技能文件树、智能体双栏、任务列表及演示工作台保持各自业务结构 |
| 浮层与交互 | 模态与非模态、层级、外部点击、焦点进入与返回、键盘关闭、滚动锁和清理 | 模板物化期间的关闭阻断由模板业务决定；基座负责执行一致的交互行为 |
| 响应式 | 容器缩放、断点、长文本、操作收纳、移动面板、可达性 | 不强制把所有插件变成同一种卡片或底部面板 |
| 主题与个性化 | 原生浅色、深色、系统主题；用户选择的界面动效 | 产物正文自身的设计不因产品外壳主题或动效偏好被静默改写 |
| 生命周期 | 样式、标记、订阅、计时器、浮层的注册与释放，失败时保留原生能力 | 各插件独立安装、缺席及卸载仍有效 |

基座组件从真实重复需求提取，不提前建设无调用方的大型组件库。现有公开导出按仓库契约门禁维护，不批量更新接口快照掩盖破坏性变化。

一致性需要三部分同时成立：共享代码被真实使用、业务例外边界明确、跨插件回归有证据。核心包完成只代表基座具备迁移条件，全产品一致性在所有消费者迁移与组合验收后成立。

- 复用真实个性化页面与已有动效消费面，做能操作的最小闭环；不以模拟组件展厅代替宿主验收。
- 为证明共享能力所需的最小消费端接线属于基座单元，改动路径事先列明；此时不顺带重设计这些业务插件。
- 验证真实设置保存、即时生效、刷新恢复、缺席回退与卸载恢复。
- 演示现有品牌语言、基础控件、关键状态、弹层和桌面／390px 的实际效果。
- 用户评审说明明确列出已迁移消费者，不能把基座示范宣称为全部插件完成。

## 5. 动效与个性化

目标是保留有价值的动效，并让用户选择；没有用户要求，不以“统一简化”为理由批量删除动效。

已在“设置 → 个性化”提供“界面设置”分组，与“助手偏好”并列。现有个性化总开关限定为协作内容的启停，不连带关闭界面偏好。主题继续使用宿主原有设置，不新增第二套主题状态。

| 界面选项 | 行为 |
| --- | --- |
| 跟随系统 | 默认值；读取 `prefers-reduced-motion`，并响应系统偏好变化 |
| 开启 | 用户显式选择标准动效；采用统一时长与交互反馈，切换系统偏好不覆盖此选择 |
| 关闭 | 停止已接入界面的非必要动画；运行、加载、等待、错误等事实仍通过静态图标和文字表达 |

作用范围为产品拥有的界面动效，包括已接入的样式动画和画布动画。不得只改变设置开关，而让实际动画保持不变。原生或第三方界面只有公开支持的契约可接入；产物中的动画、视频及演示内容保持原作品语义，不能用全局样式越界关闭。

建议实现归属：

- `@paimind/visual-experience` 在现有 `paimind.visual-experience` 命名空间中增量保存动效偏好，使用宿主修订与冲突保护，不复用已经退役的旧 `paimind-user-settings.motion` 字段。
- `@paimind/user-settings` 拥有页面分组入口；视觉插件通过公开贡献契约提供设置内容和写入操作。来源缺席时如实隐藏或显示不可用，不保存影子值。
- 共享契约定义偏好与生效状态；各插件读取解析结果，不重复读取系统偏好并各自决定优先级。来源服务缺席时采用统一的系统默认策略。
- 动效偏好不写入人设或模型上下文。动态状态提示的“功能启停”继续由扩展中心拥有，“是否动画”由界面偏好控制，两者不能混为一个开关。
- 写入失败不得显示已保存；刷新和重启后仍读权威值。旧数据缺少字段时按明确默认值读取，不猜测恢复已删除偏好。

本节记录用户的新产品要求，替代旧视觉／个性化文档中“动效只能由系统决定”的产品限制。本轮已完成三态偏好、来源持久化与最小消费路径，并同步修订两份计划及其验收条目；旧验收记录保留历史身份。

## 6. 缺陷优先级与初始核查清单

| 优先级 | 判定依据 | 处理顺序 |
| --- | --- | --- |
| 阻断 | 数据丢失、越权或错对象写入、原生会话不可用、保存或恢复破坏 | 当前单元立即优先处理；暂停视觉调整 |
| 核心流程失败 | 创建、安装、编辑、打开、执行等关键操作失败或假成功 | 在对应插件视觉调整之前关闭 |
| 交互与一致性 | 遮挡、焦点丢失、溢出、不可读长文本、状态不清、主题或语言不一致 | 结合共享根因与当前插件修复 |
| 视觉细节 | 间距、字阶、装饰、层次、动效节奏 | 核心功能与交互通过后处理 |

本轮已复现并修复设置入口切换语言后可访问名称不更新的问题，并完成动效个性化新增需求。另修正了模板测试对未随仓库交付目录的错误预期，未改模板包内容。以下其余项目仍是源码线索或历史证据缺口，不视为已确认或已修复的产品缺陷：

| 核查项 | 现有依据 | 后续证据要求 |
| --- | --- | --- |
| 业务样式影响宿主侧栏 | 智能体中心样式含宿主槽位与祖先结构选择器 | 切换中心、测试会话、侧栏收展及独立卸载后检查原生恢复 |
| 视觉包内宿主页面结构处理 | 已复现：页面切到英文后，设置按钮可访问名称仍为中文 | 已迁入兼容层并验证中英文同步、原生名称保留与卸载清理；见本轮验收 |
| 浮层关闭与层级竞争 | 多插件各自监听键盘事件、使用独立高层级数值 | 嵌套弹层、原生审批、通知和任务摘要组合操作；核对一次关闭与焦点归属 |
| 模板并发、创建中和清理警告 | 模板验收表保留未完成浏览器条目 | 真实冲突、取消、警告确认及插件卸载；核对文件和会话不损坏 |
| 历史模板回执与会话恢复 | 主线收拢记录包含相关修复及历史失败提示 | 用本轮隔离数据复现与回归；不能把旧消息当成当前失败 |
| 动效个性化缺口 | 起点只有模式字段，状态球直接读取系统设置 | 首版三态与样式／画布消费者已接通；其余插件随各自单元迁移 |
| 跨插件国际化及长文本 | 部分提案交互含固定英文，页面有独立截断规则 | 核对各插件实际语言与完整信息可达性，按产品语境处理 |

每个问题记录：影响、复现步骤、当前证据、所有者、修复范围、回归场景、结果与剩余限制。不能复现时保留为观察项，不用猜测性改动凑完成率。

## 8. 每个插件的证据与集中评审

每个插件依次完成：真实基线 → 复现已有问题 → 修复功能及状态 → 接入基座并调整界面 → 单插件及必要组合验证 → 纳入集中交付。用户集中查看效果后，再按反馈修订。

给用户的每次交付保持简短，包含：

1. 这个插件解决了什么问题，保留和改善了哪些能力。
2. 专属运行环境中的具体入口，以及可当场操作的真实效果。
3. 本轮修改前后的截图、桌面与390px状态，以及开启／关闭动效的实际表现；截图必须逐张保存并回读。
4. 已通过的真实流程、失败场景、技术门禁及尚未解决的问题。
5. 用户需要判断的视觉与交互效果；不把技术验收责任转交用户。

状态流为：待处理 → 处理中 → 技术验证通过或明确待验收项 → 集中评审。批量执行来自用户明确授权，技术验证通过仍不等于用户已确认效果。

批量执行不因单项等待效果评审而停止；缺少外部依赖的流程标记待验收并继续其他可独立工作。共享基座变更影响先前插件时补做受影响回归。

主要流程覆盖桌面与390px的三种主题；动效与嵌套弹层是共享基座的重点组合轴，每个迁移插件仍需核对其实际消费。非关键排列采用成对组合控制成本，所有未执行组合如实记录。不能用一次单包验证推断完整组合正常。

真实模型只在需要证明原生生成、创作、执行或作用域时调用。本轮真实生成的数据可以复用于不同视口和主题检查，不必每次重生成；不同业务链路不得借用另一条链路的模型结果。没有模型配置、预算或外部测试目标时，先完成可独立验证的界面与本地流程，相应真实链路保持待验收。
