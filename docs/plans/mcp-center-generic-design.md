# 通用 MCP 连接中心

## 概念与参考

MCP 是宿主连接多个服务的通用协议，服务可提供工具、资源和提示模板；飞书属于具体服务适配器。参考 [官方架构](https://modelcontextprotocol.io/docs/learn/architecture) 与 [VS Code 服务管理](https://code.visualstudio.com/docs/agent-customization/mcp-servers)。

本系统当前实现工具发现与原生工具调用，不宣称已实现资源、提示模板浏览或完整 OAuth 授权。传输沿用已验证宿主版本的 stdio 与 streamable-http，不以界面整理升级协议或依赖。

## 用户流程

连接列表 → 添加连接 → 本地程序 / 远程服务 / 来源插件模板 → 填写配置 → 在表单内测试 → 保存连接 → 智能体中心选择连接。

添加与编辑表单均提供独立“测试连接”按钮，测试直接读取当前草稿，无需预先保存。测试期间显示状态，结束后就地显示通过、失败原因或请求未完成；失败保留全部输入，修改字段后旧结果失效。保存仍是用户独立操作，不会由测试自动触发。

飞书模板仅填入已安装桥接程序的配置，归入通用添加流程，不在页面顶部占据独立入口。模板多语言由来源插件贡献；连接中心不硬编码供应商名单。测试连接仅代表握手与工具发现，不等于文档权限或完整业务流程通过。

## 所有权与兼容

- 既有 MCP 中心增强；页面、连接记录和写入服务仍由其唯一拥有。
- 原生宿主继续拥有实际 MCP 挂载、工具调用和会话生命周期，兼容逻辑集中于兼容包。
- 飞书插件拥有桥接服务、来源模板及模板翻译；不复制连接注册表。
- 模板契约仅增加可选英文元数据，旧贡献方继续有效；既有连接持久化格式不变。
- 不修改既有连接 ID、配置、版本、凭证引用、助手绑定或会话数据。失败和卸载保持已有边界。
- 本地/远程新建只产生未保存草稿；用户点击测试时才临时启动或连接对应服务，执行握手与工具发现后释放连接，不安装服务或执行业务工具。
- 草稿探测复用原生协议探测适配器，不注册连接、不写入正式测试证据、不挂载智能体工具，也不占用现有助手的配置协调队列。持久化格式与既有管理接口保持兼容，仅新增草稿测试接口。
