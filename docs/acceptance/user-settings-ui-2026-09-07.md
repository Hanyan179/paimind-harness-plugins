## 2. 本轮复现与处理

| 问题 | 真实证据与修复 |
| --- | --- |
| 设置页切换丢失草稿 | 输入文字 → 通用设置 → 个性化，原文本为空。改为插件客户端作用域拥有的临时编辑状态，切换分组和关闭后重开设置均保留草稿；放弃操作恢复保存值 |
| 未保存内容混入生效预览 | 旧“注入预览”使用草稿组装内容。首版改为展示已保存值；随后按业务用户反馈，保存内容只展示沟通风格、工作背景和回复要求，移除普通页面的原始上下文展示；草稿不进入保存内容 |
| 文字分两次保存 | 原代码逐字段提交，第一项成功、第二项失败可能产生部分保存。增加有界 `saveText` 方法，两个字段在一次原生修订检查和操作批次中提交；旧单字段方法保留 |
| 失败反馈与输入保护 | 两个标签页读取相同版本，第一页保存后第二页提交被拒绝。第二页显示错误、保留两个输入，并展示第一页的已保存内容；未覆盖宿主权威值 |
| 保存时焦点丢失 | 浏览器方向键切换个性后焦点落到页面根。调整为可聚焦的不可用语义和控制器并发保护，重验后焦点保留在选中的单选项，保存按钮也保留焦点 |
| 关闭状态不清楚 | 明确说明关闭会保留内容、仍可编辑、开启后才应用，界面偏好独立；关闭时保存不会宣称下一次回复立即应用 |
| 阅读与操作一致性 | 接入基座字号、间距、卡片、输入、单选与按钮；添加字数计数、44 像素操作目标和底部保存区。保存区使用不透明底色，避免下方文字透出 |

## 3. 契约与生命周期

`paimind-user-settings` 继续唯一拥有协作偏好。新增方法只接收 `aboutMe`、`customInstructions` 和 `expectedRevision`，结构校验拒绝额外字段，长度分别限定为 2000 和 3000。宿主只生成这两个字段的操作，不允许调用方提供路径或写入其他插件状态。

旧 `describe`、`mutate`、组件参数和公开子路径保持可用。当前真实客户端使用一次原子文字保存；缺少对应宿主方法时报告失败，不静默退回两个实际远程写入。公开通用设置作用域的既有消费者仍可使用原单字段接口。

草稿只在插件客户端作用域中存在，没有本地／会话存储、模型上下文或第二个持久化仓库。设置页切换保留草稿，重新打开时重新读取权威值，并保留仍未保存的编辑。浏览器刷新、插件重载／卸载不持久保存草稿；有未保存内容时注册浏览器原生离页提醒，释放时清理。

错误加载变为明确不可用状态并提供重试，不继续展示可写的陈旧快照。来源缺席、只读与协作关闭均不阻塞视觉插件自己的界面偏好贡献。

受保护接口变化已定向审阅：新增文字保存请求类型、类方法、远程描述以及内部编辑器声明。仅更新 `@paimind/user-settings` 的快照，本单元没有接纳其他包的接口变化。
