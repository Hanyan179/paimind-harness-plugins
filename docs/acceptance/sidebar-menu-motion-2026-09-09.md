# 品牌菜单宽度收缩修复

## 范围与所有权复核

从统一 `main` 基线 `7b18d4d08d84b25b88787cb84f87acc189f4d1c3` 派生。本次是现有菜单的呈现缺陷修复。

| 维度 | 结论 |
| --- | --- |
| 产品入口 | 仍由 `visual-experience` 的品牌菜单负责 |
| 业务实体 | 不读写业务实体，源插件仍负责入口和动作 |
| 可写状态 | 仅现有组件临时展开状态；继续消费共享动效偏好 |
| 运行时服务 | 无新增服务、依赖或公开接口 |
| 宿主适配 | 沿用 `harness-compat` 侧栏适配，无新增宿主探测 |
| 失败与卸载 | 沿用组件边界、样式和监听清理，不改变原生入口恢复 |

## 复现与修改

真实 `3080` 页面逐帧测量显示，展开菜单从 1277px 收缩至 320px，约 250ms 才稳定。原样式同时把定位从侧栏绝对定位改为视口固定定位，并过渡 `width:100%` 到固定宽度，百分比的包含块变化导致第一帧几乎铺满视口；高度与横坐标过渡进一步造成挤压感。

移除菜单及其布局的尺寸过渡，菜单内容直接采用最终尺寸。展开只做共享时长的淡入与 4px 上移，关闭即时收回；侧栏占位保持稳定，定位在绘制前计算。关闭按钮和 Escape 在入口重新可见后恢复焦点。
