# 智能体与 Skill Harness 集成契约

## 所有权

| 对象 | PAIMind | DeepSeek Harness |
|---|---|---|
| Skill 上传、检查、安装记录 | 拥有 | 不拥有 |
| Skill 发现、调用策略、注入和执行 | 不拥有 | 拥有 |
| 智能体业务表单和版本映射 | 拥有 | 不拥有 |
| Preset 文件、组合、会话绑定和模型运行 | 不拥有 | 拥有 |

## Skill 控制接口

```ts
interface SkillInstaller {
  inspectUpload(input: { uploadId: string }): Promise<SkillUploadPreview>
  installUpload(input: { uploadId: string; digest: string }): Promise<SkillInstallResult>
  listInstalled(): Promise<SkillInstallerSnapshot>
  uninstall(input: { skillId: string; version?: string }): Promise<SkillRemovalRecord>
}
```

二进制通过 `POST /paimind/skills/uploads` 流式传输；控制接口只传 `uploadId` 与摘要。

## 智能体控制接口

后台服务提供 `listProfiles`、`saveProfile`、`setDefault`、`bindSession`、`migrationPlan`、`recordMigration`、`verifySession` 和 `listAudit`。业务 UI 创建 Preset 时必须先调用 Harness `agentPreset.copy`；开始对话必须调用 `agentPreset.select`，不得构造模拟会话。

创建和编辑共用同一个 Builder（构建器）与 Profile Contract（配置契约）。创建助手使用 Harness（宿主）原生 `standard` 预设及 `@paimind/agent-builder` 唯一拥有的 `paimind-agent-authoring` 系统技能；不将 `cordis` 等内部模式包装成业务智能体、第二套预设文档或独立权限系统。主对话与智能体中心入口复用同一创建技能，只由结构化工具结果发出 Builder Request（构建器请求），不按关键词路由或自动保存。

### 原生创建会话契约

- 重连已保存创建会话或继续其后续轮次前，先经原生历史接口确认原编号可读，再以同一编号和原列表的准确工作目录调用宿主创建／恢复接口；不传替代预设、不移动工作区。恢复响应必须仍是同一编号与standard基座，随后才封锁创建能力和准备上下文。原历史缺失、目录缺失或变化、恢复被拒绝、身份／预设不符或组件卸载均失败，不另建会话或自动提交模型消息替代；正常恢复可追加原生生命周期事件，但不能改写旧历史。

- 首轮配置必须调用 Harness（宿主）原生会话接口创建 `agentPreset=standard` 的专用创建会话；后续轮次向同一个 `sessionId` 提交消息。PAIMind（插件套件）不保存第二套配置对话历史，最终智能体也以 `standard` 为基础预设。专用会话的工具限制只作用于该会话，不泄漏到普通对话。
- 每轮提交前读取原生 History（历史）基线序号；提交后只折叠本轮新增事件。只有 `turn/end` 的 `reason.kind` 为 `completed`，且本轮存在非空 `assistant/message` 时，才可以返回可见回复和 Proposal（提案）。失败、取消、超时与其他终态必须失败关闭。
- 企业消息签名保留有界的原浏览器关联编号；兼容层只从准确原生会话的历史投影该编号，创建界面据此定位本轮，不以最后一条完成消息替代。签名校验和当前登录／单元／策略授权仍由企业身份所有者执行，浏览器投影不能授权。历史中没有该字段的旧签名继续由原身份所有者校验，不补造关联；委派／任务来源不继承浏览器编号。原生 `user/message` 中的插件与技能目录注入不是人类提交；同一创建轮次的第二条人类消息，即使复用编号，也必须拒绝提案。
- Streaming（流式）只投影原生 Session Partial Blocks（部分输出块）中的可见文本，并在结构化提案标签前截断；不得把隐藏推理或提案 JSON 当作用户可见回答。
- Proposal（提案）采用字段白名单。PAIMind 只接纳业务分类、名称、用途、角色、目标、行为规范、补充要求和会话技能；技能再次过滤为真实已安装名称，基础 Preset、产品类型、身份、版本、存储与权限字段永远不能由模型写入。
- 提案可以在表单预览，但必须保留提案前快照。提案待确认时禁止下一轮配置与保存；“撤销”恢复快照，“保留更新”只确认当前草稿。模型调用和提案确认都不得触发 Preset 复制或 Profile 保存。
- 缺少原生创建会话能力、`standard` 基座或创建技能不可用、模型失败或轮次非正常完成时，界面必须显示真实错误并保留草稿，不得调用本地规则生成替代提案。

## 一致性

- 受管工具的原生审批通过后，实际工具体开始前须通过原会话写入所有者完成准确审批对的持久化检查点，并再次核对原执行身份与当前策略。关联仅来自本次原生准备区间及准确调用编号，不复用历史同名批准、不建立审批状态库。失败、无写入器、超时、取消或期间撤权均不启动工具体；晚完成的刷盘不恢复执行。此写侧检查点与只读回执核验严格区分。

- 企业执行回执的持久化证明必须从宿主 `sessionPersistence.readFrom` 读取准确原存储事件；`inspect` 在会话活动时可直接返回内存，只能作逻辑观察。回读不能顺带刷盘、修复、恢复会话或补造事件。审批的准确已存储请求／决定对与命令的载体接受回执分别核对；回包丢失时，即使原存储中观察到相同决定，也不能据此归属本命令或自动重试工具。轮次入队持久证明遵守同一存储边界。

- 企业受管会话的原生审批答复保留宿主原待处理请求及关联编号。网关核对本人会话、准确审批版本和当前预设，将决定与关联摘要绑定原身份签名；原答复适配在观察原待处理请求前后验证当前主体，最终由原所有者同步消费，私有证明不写原会话历史。批准须具备当前执行资格，拒绝仅保留当前登录下的停止清理；批准不替代原工具执行时门禁。错误／过期／已结束／并发落后答复不重建审批，普通原生问题答复不改写。载体接受不等于持久决定、工具完成或版本化公开接口验收。

- 受管原生冷会话列表的当前预设，由共享兼容层调用原生非发布检查器和 `resolveSessionPreset` 修正；原列表身份、顺序与其他投影保持。不得把创建头当作当前选择，不得为列表读取恢复活动智能体、写历史或另建缓存。读取失败／取消／卸载／超时明确失败；此显示修正不能授予执行资格。

- Preset 保存使用目录级 staging/backup/rename；写入失败恢复原目录。
- `expectedVersion` 作为编辑冲突保护。
- 会话绑定同时记录 `sessionId + presetId + configVersion`。
- 写入普通绑定和迁移记录前，必须通过兼容层回读原生活动会话或原生持久化检查器，核对准确身份和首轮有效预设；不存在、其他单元、历史损坏或预设不一致均拒绝。历史检查不得顺带创建或恢复活动会话。
- 企业网关对显式预设的原生会话创建检查当前发布／分配／依赖资格；分叉则通过准确运行单元的私有控制通道读取原生来源会话，仅返回身份、当前实际预设和已结束轮次边界。当前预设复用宿主 `resolveSessionPreset`，不能仅使用创建头或调用方声称的预设；未结束来源、不可读来源和当前无资格均不转发分叉。此投影无独立持久状态，不公开会话正文。无显式选择的既有会话恢复保留原生历史语义，不等于重新获得执行许可；后续每轮模型／工具仍受当前企业执行门禁约束。
- 无显式预设的创建必须先区分新建与原生历史恢复，包括调用方已提供会话编号的情况。活动会话或原持久化所有者证明存在时沿原历史恢复；只有原持久化修订读取明确不存在才可按新建处理，读取失败不能当作不存在。新建由原预设所有者解析当前默认值，完成现行资格检查后固定该选择再转发，保留原请求编号、工作区与会话编号；不得硬编码默认预设、扫描文件建立影子目录或把已撤权历史重新赋予执行权限。私有读取随原运行作用域释放，不新增公开调用入口。
- 受管成员与管理员提交新消息、子会话续写或编辑／提前执行排队消息前，网关必须按准确私有单元回读原生会话的当前预设，再检查现行发布／分配／依赖资格；读取或治理不可用、身份／运行绑定／预设变化均拒绝，不能先把拒绝消息写进原会话再依赖模型错误反馈。此检查使用原身份所有者的资源审计入口，拒绝记录关联同一请求和当前主体，审计失败仍不得转发。原生每轮模型／工具守卫继续重新授权。取消和移除排队消息属于停止／清理，保留原生所有者与当前登录检查，不因资源撤回而禁止；开发管理员的显式非受管载体不算企业验收。
- 同一提交前资格与审计门禁也覆盖原生会话改名、模型选择，以及目标创建／编辑／恢复／完成／清除，不能只阻止消息发送而允许修改撤权历史。原生历史、已引用附件读取和目标暂停保留各自所有者检查；工作区编排属于独立所有权，不按名称误判为会话正文写入。预设读取／选择／显式创建／分叉的来源与资格拒绝，以及原生返回期间发生撤权的拒绝，同样必须进入原身份审计入口，审计失败不得转发写入或返回受限内容，不增设审计存储。
- 智能体服务在同一写队列内核对配置版本和写入绑定；不能覆盖已有真实用户轮次的历史绑定版本。迁移须核对原绑定、服务端重新生成的计划和不同的原生目标会话；完全相同的重试保留原回执，伪造或冲突重试不写入。
- 删除个人智能体也进入同一写队列，重新读取配置和全部持久绑定，保持排他直到原生预设所有者完成删除；存在历史引用则拒绝。状态文件仅在不存在时视为首次使用；读取错误、损坏内容、未知版本、无效绑定／迁移／验证记录均失败关闭，保留原文件，不返回空历史或用新写入覆盖。旧记录未指定会话用途仍合法；这些产品引用保护不替代宿主对未登记原生引用的生命周期保护。
- 验证结果只能由服务端生成：通过兼容层回读原生活动或冷历史会话，核对身份、首轮有效预设及当前配置与绑定版本；首个人类轮次必须有匹配的原生开始／正常结束事件，且已完成步骤内存在同轮、未中断、可见的模型来源回复。排队批次仍属同一轮次，后续轮次不能补证失败首轮；工具／推理／隐藏草稿、失败／取消／运行中的部分回复不能算通过。既有 `recordVerification` 输入只作为对服务端回读结果的断言，伪造字段或不可读历史不写审计，准确重试保留原回执；界面使用 `verifySession`，不自报验收通过。这是会话运行证据，不替代真实浏览器及业务效果验收。
- 创建助手的 AI（人工智能）验证与保存后智能体验证分开记录：前者必须通过创建参数、创建结果或原生会话头证明创建会话使用 `agentPreset=standard`、有效创建技能和专用作用域，并完成真实模型轮次；后者必须证明测试会话选择保存后的 `presetId + configVersion`。两类证据不能相互替代。
- Builder 的测试对话只能运行已保存配置，并必须选择该 Profile 对应的同一个 `presetId + configVersion`；未保存草稿不得复制临时 Preset 或伪造测试 Agent。
