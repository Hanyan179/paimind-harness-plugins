# RQ-103 平台级定时任务 PRD

> 状态：Activated in Local Main Profile / Pre-acceptance Passed（已进入本地主配置／预验收通过）。`@paimind/platform-scheduler` 是 PAIMind 唯一启用的定时任务产品与运行时；旧的 Harness Session Reminder（会话提醒）插件不再进入 PAIMind `3080` 组合。

## 一句话定义

PAIMind 定时任务是平台级 Time Trigger（时间触发）能力：业务用户选择开发者已登记的执行事项并配置时间，平台按时触发、记录运行结果；执行方负责业务逻辑、数据权限、人工处置页面和后续操作。

Harness Session（会话）是平台执行事项可选择的一种 Adapter（适配器）目标，不是第二种定时任务。上游原生 Schedule（会话提醒）能力仍可独立安装，但当前 PAIMind 产品不装载、不展示，也不维护第二套入口。

## 目标用户与角色

| 角色 | 负责 | 不负责 |
|---|---|---|
| 业务用户 | 创建、编辑、启用／暂停定时任务；选择立即运行；归档任务；查看运行记录与结果 | 配置接口、鉴权、回调或业务参数 |
| 业务开发者 | 用代码登记事项；实现业务逻辑；按契约回传结果 | 实现时间计算、任务列表和平台运行记录 |
| PAIMind Scheduler | 保存时间规则与 `actionId`；生成 Run；触发 Adapter；记录结果和审计 | 理解飞书、发票、项目或 AI 的业务字段 |
| Adapter | 将统一触发请求转换为目标系统调用；验证目标链接 | 在 Scheduler Core 增加目标系统分支 |
| 业务系统 | 执行、鉴权、数据权限、结果页、人工处理 | 维护 PAIMind 的时间与运行记录 |

## 信息架构

定时任务只有两个一级 View（视图）：

1. 任务列表：任务、执行事项、时间规则、状态、下次执行、最近结果、操作。
2. 运行记录：计划时间、实际开始、状态、结果说明、可选操作入口。

任务列表只展示业务摘要，不展示 `scheduleId`、时区、事项来源、触发方式或结果全文；这些信息或者属于开发内部标识，或者已经在运行记录与编辑表单中存在。运行记录承担触发方式、完整结果说明和后续操作入口。

不提供“成功列表”“失败列表”“待处理列表”等重复一级页面；状态是筛选与 Badge（状态标识），不是新的信息架构。`progress` 只在 `running` 状态以文字百分比出现，不使用持续占位的进度条。

唯一业务入口位于 Harness **设置 → 平台定时任务**，选中后在设置内容区直接展示“任务列表 / 运行记录”，不设置说明中转页或“打开任务列表”二次操作。侧边栏、会话页和 Extension Center（扩展中心）不再提供第二个快捷入口，避免同一能力出现两套入口与状态。

任务列表排序固定为：正在调度且存在下次执行时间的任务优先，并按 `nextRunAt` 从近到远排列；暂停、已执行等非活动任务随后，按最近更新时间倒序排列。运行记录按触发时间从新到旧排列。

## 创建与编辑

业务表单只包含：

| 字段 | 必填 | 规则 |
|---|---|---|
| 任务名称 | 是 | 1–160 字符，用户可编辑 |
| 执行事项 | 是 | 仅选择开发者已登记且启用的事项 |
| 执行周期 | 是 | 一次、每天、每周、每月 |
| 执行时间 | 是 | 一次为完整日期时间；周期任务为本地时间 |
| 星期／日期 | 条件必填 | 使用下拉框选择星期；每月日期使用 1–28 下拉框 |
| 时区 | 是 | 使用 IANA Time Zone（IANA 时区）下拉框，默认浏览器时区 |
| 定时状态 | 是 | 启用未来自动执行，或暂不自动执行；不控制“立即运行” |

禁止出现负责人、截止时间、匹配模式、项目范围、冲突策略、业务模板、调用地址、鉴权、回调、第三方字段、事件触发、补跑和 Cron（表达式）。“立即运行”是任务保存后的独立操作，不是表单字段。

执行事项目录按稳定类别分组展示：`ai`（AI 与 Agent）、`integration`（业务系统）、`message`（消息发送）、`health-check`（健康检查）。类别只帮助用户定位事项，不产生不同的调度表单。当前内置 `Agent · 新建会话并生成工作区简报`，每次运行创建独立 Agent Session；飞书机器人是由消息 Adapter 登记的另一种事项。其他业务系统按相同合同自行登记。

## 时间与恢复规则

- UTC 保存发生时间，IANA 时区解释日历规则。
- 使用标准 Temporal（时间）库处理夏令时；不存在的本地时间采用 compatible disambiguation（兼容消歧）。
- 每月仅允许 1–28，避免跨月缺日的隐式业务决策。
- 停机恢复只执行最近错过的一次；不批量补跑。
- 每个任务禁止并行重叠；前一 Run 未结束时不创建同任务的新 Run。
- 一次任务派发后进入已执行状态，不再显示“启用”；需要再次定时执行时选择“编辑”，设置未来时间并保存。
- “立即运行”会真实触发当前登记事项并生成独立 Run，但不改变任务状态、时间规则或 `nextRunAt`。
- 同一任务已有 `queued` 或 `running` Run 时，禁止再次选择“立即运行”。
- 已登记事项的执行器未装载时，事项视为当前不可用：不能用于新建、编辑或立即运行；已有到期任务保留原计划且不生成失败 Run，待事项恢复后再触发。

## 状态

任务状态：`enabled`、`paused`、`archived`。

运行状态：`queued` → `running` → `succeeded | failed | needs_attention`。

每条运行记录同时标记触发方式：`schedule`（定时触发）或 `manual`（手动触发）。

- 最终状态必须有纯文本 `message`。
- `progress` 仅允许在 `running`，范围 0–100。
- 归档后默认列表隐藏任务，但保留运行记录和审计。
- 重复触发由确定性 `runId` 与 `idempotencyKey` 去重。

## 用户操作

| 操作 | 用途 | 是否改变任务状态 | 是否改变下次执行 |
|---|---|---|---|
| 启用／暂停 | 控制未来是否自动执行 | 是 | 是，启用时重新计算 |
| 立即运行 | 立即真实执行一次当前事项 | 否 | 否 |
| 编辑 | 修改名称、执行事项、周期、时间、时区或定时状态 | 取决于保存内容 | 取决于保存内容 |
| 归档 | 从默认任务列表移除并保留历史 | 是 | 清除 |

“立即运行”与正常定时触发使用同一个 Adapter、结果合同、重试与安全边界，区别仅在触发来源和是否影响日历计划。它不是无副作用的沙箱测试，因此页面不得使用“测试运行”或“试运行”误导用户。

## 执行流程

### Harness Session 事项

1. 到点生成独立 Run。
2. Harness Adapter 为该 Run 创建新的 Session。
3. Adapter 使用开发者在代码中登记的工作目录、Agent Preset（智能体预设）和模型配置创建 Native Job，并向新 Agent 提交登记的 Prompt（指令）；这些执行配置不进入业务表单。
4. Session 创建并开始执行后，Adapter 立即向 Scheduler 返回 `accepted`，避免把 Agent 执行时长误当成派发超时。
5. Agent 结束后由 Adapter 异步回传成功、失败或待处理结果。
6. 运行记录提供“打开会话”，选中准确的新 Session。

### 外部业务系统事项

1. HTTP Adapter 向登记的 HTTPS 地址发送签名触发请求。
2. 业务系统验证签名与幂等键并立即返回 `202 Accepted`。
3. 业务系统异步回传 `running` 和最终结果。
4. 可选操作链接必须命中登记的 Origin Allowlist（来源白名单）。
5. PAIMind 仅在新标签页打开链接，不嵌入或复制业务页面。

## 失败、重试与超时

- 派发连接或非 `202` 错误最多尝试 3 次，退避由部署配置控制。
- 已被执行方接受后的业务失败不自动重跑，避免重复业务副作用。
- 24 小时未收到最终回调，Run 标记失败；阈值可由部署配置调整。
- Adapter 不可用时仅影响其事项；其他 Adapter 与平台任务继续工作。

## 权限与安全

- 调用方身份和消息来源由 Service Credential（服务凭证）解析，不接受请求体伪造。
- 服务请求采用 HMAC-SHA256、时间戳、唯一 Request ID（请求标识）和重放保护。
- 任务、运行、日志和浏览器载荷不保存密钥，只保存 Credential Reference（凭证引用）。
- 外部地址必须是无内嵌凭证的 HTTPS，阻止 localhost 与私网 IP；生产还必须配置网络出口策略。
- 当前 Harness 匿名身份不能冒充企业授权。正式企业部署需要可信 Authorization Provider（授权提供方）。

## 明确不做

- 不开发业务系统页面、发票表格、飞书任务详情或人工处理逻辑。
- 不允许业务用户填写接口与业务参数。
- 不提供事件触发、Cron、固定间隔、批量补跑和多节点抢占；立即运行只允许执行已登记事项，不允许填写临时业务参数或绕过权限。
- 不在 PAIMind 产品中继续暴露 Harness 原生会话提醒或第二套定时插件。
- 不把本地自动化测试宣称为共享环境正式验收。

## 验收标准

1. 页面只有任务列表与运行记录两个一级视图。
2. 表单只出现本文定义的业务字段；时区、星期和每月日期使用下拉选择。
3. 一次／每天／每周／每月与 DST（夏令时）计算通过测试。
4. 确定性 Run、幂等、禁止重叠、最近一次补跑、归档保留历史均有自动化证据。
5. Harness 事项创建独立 Session 和 Native Job，结果可打开准确 Session。
6. HTTP 事项验证签名、`202`、重试、回调、重放与链接白名单。
7. 外部业务页面只通过隔离的新标签页打开。
8. 当前 Bundle、技术插件列表和产品入口只存在平台 Scheduler，不装载 `@deepseek-ai/dsh-schedule`、`@deepseek-ai/dsh-time-context` 或已退役的 Session-local facade。
9. Light／Dark、桌面／窄屏／移动宽度无溢出、遮挡或控制台错误。
10. “立即运行”生成标记为 `manual` 的独立 Run，任务状态和 `nextRunAt` 保持不变；一次性任务执行后通过“编辑”选择未来时间，页面不得出现重复的“重新安排”操作。
11. 共享测试环境存在时才可标记 Formal Acceptance Passed（正式验收通过）；否则为 Pre-acceptance Passed（预验收通过）。
12. 产品入口只存在于“设置 → 平台定时任务”；任务列表遵循“活动任务按下次执行升序，其他任务按更新时间倒序”，运行记录按触发时间倒序。
13. 事项执行器未装载时，不得继续显示为可选事项或消耗到期计划；恢复登记后原计划可以继续派发。
14. 执行事项按 AI 与 Agent、业务系统、消息发送、健康检查分组；至少能选择 Agent 新会话事项与飞书机器人事项，类别不得派生额外业务字段。
15. 任务列表不显示技术标识、时区、事项来源、触发备注或结果全文；完整结果与操作入口只进入运行记录。
