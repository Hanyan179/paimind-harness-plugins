# RQ-104 平台级通知 PRD

> 状态：Implemented in Local Main Profile（已进入本地主配置）。当前交付包含通知中心、公共 SDK／API 契约和自动化验证；共享环境发布仍需独立 Release Gate（发布门禁）。

## 一句话定义

PAIMind 通知是平台级 Message Delivery（消息投递）能力：业务系统按统一接口发送“给谁、说什么、重要程度、可选跳转链接”，平台识别可信来源、统一展示并记录阅读状态。

通知不理解发票、审批、项目或 Agent 的业务流程。业务系统负责产生消息、目标页面、数据权限和后续操作；PAIMind 只提供消息壳子与安全跳转入口。

## 目标用户与责任边界

| 角色 | 负责 | 不负责 |
|---|---|---|
| 业务用户 | 查看全部／未读通知、标记已读、打开相关页面 | 配置接口、渠道、鉴权、消息模板或接收策略 |
| 业务开发者 | 调用 SDK／API；提供接收人、标题、正文、级别、幂等键和可选链接 | 伪造来源、选择平台渠道、开发 PAIMind 内部页面 |
| PAIMind Notification | 校验调用、绑定可信来源、去重、持久化、展示和记录已读 | 理解业务状态、执行审批、保存业务数据 |
| 业务系统 | 业务逻辑、目标页面、权限、人工处理和后续动作 | 维护平台通知中心与阅读状态 |

## 产品信息架构

通知只提供一个 Notification Center（通知中心），包含：

- 全部、未读两个筛选。
- 来源、标题、可选正文、级别、时间、阅读状态。
- 单条标为已读、全部已读。
- 可选的相关页面按钮。

不按“业务、系统、AI、定时任务”建立固定来源枚举；来源名称来自调用方绑定的 Service Credential（服务凭证）。不建立审批、阻塞、完成、共享等固定业务事件设置，不提供平台内的业务处理表格或详情页。

通知中心是被动接收器，不监听或推断 Tool、Job、Session、Schedule、Artifact 等平台事件。只有业务应用或平台模块通过可信 Producer、SDK 或 API 显式调用通知能力时，才写入一条消息。任何类型的产物生成、成功、失败或修订都不会自动产生通知；调用方确实需要通知时，由调用方明确决定内容、级别、接收人与跳转目标。

## 业务用户配置

当前版本不提供用户级 Receive Range（接收范围）开关，也不在 Personalization（个性化）中放置通知设置。所有经过可信生产者校验的通知进入通知中心；用户可以筛选未读和管理阅读状态。

业务用户不配置来源、接口、鉴权、回调、消息模板、接收策略或发送渠道。渠道路由属于未来平台能力；未实际接入的渠道不得在页面展示为可用配置。

## 外部调用契约

业务系统通过独立的 `@paimind/platform-sdk` 调用：

```ts
await client.notifications.send({
  recipientIds: ['user:123'],
  title: '发票已生成',
  body: '请查看并确认本次发票。',
  level: 'success',
  link: {
    label: '查看发票',
    url: 'https://billing.example.com/invoices/123',
  },
  idempotencyKey: 'invoice:123:ready',
})
```

字段规则：

| 字段 | 必填 | 业务含义 |
|---|---|---|
| `recipientIds` | 是 | 平台接收人标识，1–500 人 |
| `title` | 是 | 通知标题，1–240 字符 |
| `body` | 否 | 纯文本正文，最多 4,096 字符 |
| `level` | 否 | `info`、`success`、`warning`、`error`；默认 `info` |
| `link` | 否 | 跳转按钮的 `label` 与 HTTPS `url` |
| `idempotencyKey` | 是 | 调用方业务事件唯一键，用于重试去重 |

`source` 与发送渠道不是请求字段。平台从服务凭证获得来源，不能由调用方伪造。

## 链接与安全

- `link.url` 必须是无内嵌用户名与密码的 HTTPS 地址。
- `link.label` 必须是清晰的业务动作，例如“查看发票”“打开人工处置”，不能使用裸 URL。
- 前端使用新标签页与 `noopener,noreferrer` 打开，并清除 `window.opener`。
- 目标页面完全由业务系统开发和维护；PAIMind 不嵌入、不复制、不代理页面内容。
- 服务调用使用 HMAC-SHA256、时间戳、唯一 Request ID（请求标识）和重放保护。

## 状态与展示语义

公开级别保持稳定代码值，通知中心转换为业务语言：

| 代码值 | 中文展示 | 英文展示 |
|---|---|---|
| `info` | 提醒 | Notice |
| `success` | 已完成 | Completed |
| `warning` | 需关注 | Attention |
| `error` | 失败 | Failed |

级别只影响表达，不承担业务流程状态机。业务系统不得依赖 PAIMind 通知的“已读”状态推进业务流程。

## 明确不做

- 不提供“发送通知”业务页面；业务系统通过 SDK／API 调用。
- 不允许调用方指定应用内、浏览器、飞书或其他渠道。
- 不开发业务详情、审批、人工处置、重试或数据表格。
- 不将定时任务执行状态、Agent 会话状态或业务对象复制为通知领域状态。
- 不展示尚未接入的渠道与无真实消费者的配置占位。

## 验收标准

1. 通知中心只包含全部、未读、消息列表、阅读操作和可选相关页面入口。
2. 消息展示可信动态来源、标题、纯文本正文、业务化级别、时间和阅读状态。
3. Personalization（个性化）与其他设置页不出现通知接收策略；通知中心只提供全部／未读和阅读状态操作。
4. SDK／API 使用 `link`，不使用含义含混的通知 `action` 字段。
5. 请求不能设置来源或渠道；来源由服务凭证绑定。
6. 重复 `idempotencyKey` 不产生重复消息。
7. 外部链接只接受无凭证 HTTPS，并以隔离新标签页打开。
8. 长正文与恶意 HTML 按纯文本展示，不执行标签或脚本。
9. 业务系统页面不进入 PAIMind 页面、数据模型或操作逻辑。
10. 任意产物生成、成功、失败或更新都不自动新增通知；只有可信调用方显式发布才新增消息。
11. SDK、API、通知中心、类型检查和生产构建通过验证；本地浏览器确认布局、阅读操作、外链入口与控制台无新增错误。
