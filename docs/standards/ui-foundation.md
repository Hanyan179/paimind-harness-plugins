# UI Foundation（界面基座）首版契约

状态：已扩展到本轮可检查的客户端界面；逐插件证据仍按[长期计划](../plans/ui-quality-foundation-roadmap.md)逐项评审。本契约说明公共界面定义的使用方式，插件编写与生命周期要求仍以 [Plugin Authoring（插件编写规范）](plugin-authoring.md) 为准。

## 1. 所有权与一致性

| Owner（所有者） | 职责 |
| --- | --- |
| `@hansen/ui-foundation` | 语义颜色、间距、字号、圆角、控件、焦点、反馈状态和动效解析契约；无业务状态和持久化 |
| `@hansen/visual-experience` | 品牌主题覆盖、界面偏好保存、共享动效投影及其卸载恢复 |
| `@hansen/harness-compat` | 宿主版本与页面结构适配；设置入口语言同步、导航图标与切页滚动复位 |
| `@hansen/user-settings` | 个性化页面、助手偏好和可选界面偏好子插槽；不保存其他来源的偏好 |
| 各业务插件 | 领域数据、页面布局与完整交互；消费共享定义 |

共享包提供一致性的基础。每个插件完成接入、真实页面检查和用户评审后，才算该插件符合基座；公共包存在不代表所有界面已经统一。

## 2. Design Tokens（设计变量）

客户端在自己的受生命周期管理的样式节点中引入 `PAIMIND_UI_FOUNDATION_CSS`，并给自己拥有的界面根节点标记 `data-paimind-ui-scope`。宿主主题仍为颜色来源，插件不复制另一套浅深色状态。动态创建的样式在插入页面前调用兼容层 `markHarnessClientStyle(style, packageName)`；它写入当前宿主热更新所需的归属标记，避免被下一插件认领并误删。样式的创建和卸载仍由来源插件负责。

| 类型 | 变量 | 使用规则 |
| --- | --- | --- |
| 颜色 | `--paimind-ui-canvas/panel/subtle/border/text/muted/faint/accent/danger/success/warning` | 按用途取色，不按具体色值命名 |
| 间距 | `--paimind-ui-space-1/2/3/4/6` | 对应 4/8/12/16/24 像素；密度由布局组合决定 |
| 字号 | `--paimind-ui-text-sm/md/lg` | 对应 12/14/20 像素 |
| 圆角 | `--paimind-ui-radius-sm/md/lg` | 对应 8/12/16 像素 |
| 控件 | `--paimind-ui-control-height` | 基础高度 36 像素；触屏卡片保持更大的完整点击区域 |
| 阴影 | `--paimind-ui-shadow-overlay` | 浮层使用；普通内容卡片以边框分组 |

## 3. Primitives（基础样式）

已有的 `data-paimind-ui-panel/card/button/summary` 保留；新增 `field/choices/choice/state`。这些是样式接口，调用方仍使用有语义的原生按钮、文本框、单选框与标题。

- 单选组使用 `role="radiogroup"`、可读名称、原生单选框和完整可点击标签；支持方向键和焦点可见。
- 反馈使用 `role="status"`；保存失败使用 `role="alert"`，保留当前值并提供重试方式。只读、加载中、保存中与错误不能合并成一个空白状态。
- `data-paimind-ui-state` 支持 `neutral/success/error`；状态必须有文字，颜色只提供辅助信息。
- `data-paimind-ui-switch` 提供 44 像素操作区域、轨道和滑块；插件只决定它在页面中的位置，共享选择器不得覆盖调用方布局。
- `handlePaimindTabKey` 统一局部标签组的方向键、首尾跳转、循环焦点与激活，跳过不可用条目和嵌套标签组；调用方管理选择状态与 `tabIndex`。
- 窄屏按钮、表单控件与单选标签保留至少 44 像素点击区域。
- 控件在窄屏换行，内容区允许纵向滚动；不通过裁掉操作或文字制造“适配”。
- 不替换宿主已有的焦点管理、弹层或会话选择状态。本轮没有新建通用弹窗管理器。

### 面向业务用户的命名与文案

所有业务页面按用户要理解的对象、输入内容和操作结果命名。标题、字段标签、示例、按钮、保存内容、状态反馈、可访问名称和中英文翻译使用同一套术语；不能只改标题，留下另一套表单或预览名称。

- 字段使用具体名称，如“工作背景”“岗位与职责”“回复要求”；避免“关于你”“特别要求”等无法说明填写范围的名称。
- 说明回答“填什么、有什么用、何时生效”，示例使用客户跟进、销售分析、经营汇报等可理解的业务场景，示例不得保存为用户事实。
- 按钮说明动作及对象，如“查看已保存内容”“撤销未保存内容”；准确区分已保存、未保存、关闭和失败。
- 普通页面不展示原始上下文、结构标记、宿主恢复过程等实现信息。确有用户决策价值的技术信息放在明确的开发者入口，不能仅换个标题继续堆在业务流程中。
- 调整显示名称不更名持久化字段、枚举值或公开接口；存量用户内容、功能和动效选择保持原有语义。

个性化页面使用“界面设置”和“助手偏好”分组；`personality` 显示为“沟通风格”，`aboutMe` 显示为“工作背景／岗位与职责”，`customInstructions` 显示为“回复要求／内容与格式要求”。后续插件按同一原则逐项审阅，不把当前页完成表述为全系统文案已统一。

## 4. Motion（动效）

唯一持久字段为 `paimind.visual-experience.motion`，底层宿主规范化为 `paimind-visual-experience.motion`。历史 `paimind-user-settings.motion` 不恢复。

| 偏好 | 实际行为 |
| --- | --- |
| `system`（跟随系统，默认） | 根据 `prefers-reduced-motion`，并响应系统后续变化 |
| `on`（开启） | 显式启用已接入的动效，即使系统设置减少动效 |
| `off`（关闭） | 已接入的界面过渡使用零时长，状态球静止；保留状态与文字 |

`resolvePaimindMotion` 是唯一解析规则。来源插件调用 `installPaimindMotionPreference` 发布临时页面投影；其他客户端通过 `readPaimindMotion`、`subscribePaimindMotion` 消费。页面属性用于跨独立客户端包通信，不作为第二份持久化。来源卸载后清理属性和监听器，消费者回到系统偏好。

`PAIMIND_MOTION_CSS` 仅提供 `--paimind-motion-fast/enter/slow/loop/iterations`。拥有动画的样式显式消费这些变量。只需要动效变量的根节点使用 `data-paimind-motion-scope`。不得新增覆盖整页任意动画的通配规则。

接入范围和实测状态见[全插件界面检查](../acceptance/all-plugin-ui-2026-09-07.md)。本轮自有界面过渡和加载提示消费统一时长；循环动效使用 `iterations`，关闭时为 0，避免零时长无限循环。任务详情的自动滚动也消费同一偏好。生成内容中的动画和视频、第三方插件自己的动效保持各自语义。

## 5. 可选贡献与恢复

个性化页面在其原生设置条目声明 `paimind.personalization.appearance` 子插槽。视觉体验插件通过原生插槽等待并贡献自己的界面，无互相依赖的服务或持久化。

个性化页面缺席时，同一界面组件出现在通用设置中；页面存在时通用设置不重复呈现。视觉体验插件缺席时界面偏好贡献消失，助手偏好仍可用。助手偏好关闭、不可用或加载中，不影响界面偏好。动效字段不进入智能体上下文。

## 6. 后续插件的完成标准

每个插件记录消费的变量、基础样式与动效，完成浅深色、窄屏、键盘、状态反馈、保存与恢复、来源缺席及卸载检查。提供本轮截图和真实操作证据；测试、组合、浏览器验收和用户接受分别记录。按当前长期计划的执行授权批量检查，集中交付用户评审。
